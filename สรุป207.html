1.1 Optimization คืออะไร — เริ่มจากศูนย์จริงๆ

สัญชาตญาณก่อนสมการ: นึกว่าคุณกำลังหาสูตรเค้กที่อร่อยที่สุด คุณปรับ 3 อย่าง: อุณหภูมิเตา เวลาเผา ปริมาณน้ำตาล ลองสูตรหนึ่ง → ชิม → ให้คะแนน ลองอีก → ชิม → ให้คะแนน แล้วใช้คะแนนพวกนั้นนำทางไปหาสูตรที่คะแนนสูงสุด นี่คือ optimization ทั้งหมด: มีตัวแปรที่ปรับได้ มีเครื่องให้คะแนน และเป้าหมายคือทำคะแนนให้ดีที่สุด

นิยาม: การหาค่าเหมาะที่สุด = การหา $x$ จากปริภูมิค้นหา $S$ ที่ทำให้ $f(x)$ ต่ำที่สุด (minimize — มินิไมซ์: ทำให้น้อยสุด) หรือสูงที่สุด (maximize — แม็กซิไมซ์: ทำให้มากสุด)
$$\min_{x \in S} f(x)$$อ่านว่า "มินิไมซ์ เอฟ-ออฟ-เอ็กซ์ โดยที่เอ็กซ์อยู่ในเอส" = หา x ที่ทำให้ f ต่ำสุด โดย x ต้องเป็นคำตอบที่อนุญาตเท่านั้น
สัญลักษณ์ (อ่านว่า)คืออะไรทางกายภาพภาษาคนทั่วไป + ทำไมต้องมี
$x$ ("เอ็กซ์")ชุดตัวแปรที่ปรับได้ (มักเขียนเป็นเวกเตอร์ = กล่องตัวเลขหลายช่อง)"สูตรเค้ก" — สิ่งที่เรากำลังหา ถ้าไม่มี x ก็ไม่มีอะไรให้ปรับ
$f$ ("เอฟ")เครื่องจักรที่รับ x ไปแปลงเป็นตัวเลขคะแนนเดียว"เครื่องชิม" — กฎการให้คะแนน เช่น ยิ่งไม่อร่อยคะแนนยิ่งสูง
$S$ ("เอส")เซต (set — เซ็ต: กลุ่ม/ชุด) ของคำตอบที่อนุญาตทั้งหมด"ขอบเขตที่เดินได้" — กันคำตอบไร้สาระ เช่น อุณหภูมิติดลบ
$\mathbb{R}^n$ ("อาร์-เอ็น")ปริภูมิของเวกเตอร์จริง n ช่อง"ตารางพิกัด n ช่อง" — $\mathbb{R}^3$ = ตัวเลข 3 ค่าต่อกัน 1 ชุด

เคล็ดลับ: ปัญหา "maximize g(x)" สามารถพลิกเป็น "minimize −g(x)" ได้เสมอ (ทำให้ค่าสูงสุดกลายเป็นค่าต่ำสุด) เพราะฉะนั้นต่อจากนี้เราพูดถึง "การ minimize" อย่างเดียวพอ — ทิศทางเดียว ง่ายต่อการคิด

🩵 ตัวอย่างจับมือทำ 1.1 — ปัญหา optimization จิ๋วให้เห็นภาพทั้งระบบ โจทย์: หา x ที่ทำให้ $f(x) = (x-3)^2 + 1$ ต่ำสุด บนช่วง $S = [0, 6]$ (x ห้ามออกนอก 0 ถึง 6)
ลองแทนค่าทีละจุด (แต่ละบรรทัด = "ชิม" 1 ครั้ง):
• x = 0 → $f(0) = (0-3)^2 + 1 = 9 + 1 = 10$
• x = 2 → $f(2) = (2-3)^2 + 1 = 1 + 1 = 2$
• x = 3 → $f(3) = (3-3)^2 + 1 = 0 + 1 = 1$ ← ต่ำสุดที่เจอ
• x = 5 → $f(5) = (5-3)^2 + 1 = 4 + 1 = 5$
อ่านผล: คำตอบที่เสนอ (x) = ตัวเลขเดียว / เครื่องชิม (f) = ยกกำลังสองบวกหนึ่ง / คะแนนที่วัดได้ (y) = 10, 2, 1, 5 ตามลำดับ → ดีที่สุดคือ x = 3 (ได้คะแนน 1) — จบ เข้าใจง่าย นี่คือรูปแบบคิดของทั้งวิชา

1.2 องค์ประกอบ 3 อย่างของปัญหา Optimization (หัวใจข้อสอบ)

ทุกปัญหา optimization ไม่ว่าเล็กหรือใหญ่ มี 3 อย่างเสมอ — นี่คือหัวข้อที่ออกสอบบ่อยมาก:

  1. Candidate solution $x$ (แคนดิเดต โซลูชัน — คำตอบที่เสนอ): คำตอบ 1 ชุดที่กำลังลอง เช่น สูตรเค้ก 1 สูตร, น้ำหนัก (weights — เวทส์: ค่าพารามิเตอร์) ของโมเดล AI 1 ชุด
  2. Objective function $f(x)$ (ออบเจกทีฟ ฟังก์ชัน — ฟังก์ชันเป้าหมาย): เครื่องให้คะแนนว่าคำตอบนั้นดี/แย่แค่ไหน
  3. Evaluation cost $y$ (อีวาลิวเอชัน คอสต์ — ผลการประเมิน): ตัวเลขที่ได้ออกมาเมื่อเสียบ x เข้า f — เขียนว่า $y = f(x)$
$$y = f(x)$$"เสียบสูตร x เข้าเครื่องชิม f → ได้คะแนน y ออกมา" — สายพาน x → f → y คือหัวใจของทุกอย่างในวิชานี้
สัญลักษณ์คืออะไรทางกายภาพภาษาคนทั่วไป
$y$ ("วาย")ตัวเลขผลลัพธ์ที่วัดได้จากการประเมิน 1 ครั้ง"คะแนนที่ได้จากการชิม" — เป็นผลลัพธ์ ไม่ใช่สิ่งที่เราเลือกเอง
$f(x)$ ("เอฟ ออฟ เอ็กซ์")กระบวนการประเมินคำตอบ x"การเอา x ไปผ่านเครื่องชิม" — สังเกตว่าเขียนติดกันเพราะ x ถูก "ป้อน" เข้าไปใน f
🩵 ตัวอย่างจับมือทำ 1.2 — หา 3 องค์ประกอบจากสถานการณ์จริง (โจทย์แบบนี้ออกสอบบ่อย) สถานการณ์: คุณจูน (tune — ทูน: ปรับแต่ง) การตั้งค่าโมเดล AI ด้วย 2 ค่า: อัตราการเรียนรู้ และขนาดชุดข้อมูลต่อรอบ แล้วเทรนโมเดลจริงเพื่อดูความคลาดเคลื่อน
แยกทีละองค์ประกอบ:
• x (คำตอบที่เสนอ) = คู่ค่า (อัตราการเรียนรู้ = 0.01, ขนาดชุด = 64) ← 1 ชุดการตั้งค่า = คำตอบ 1 ชุด
• f (เครื่องให้คะแนน) = กระบวนการ "เอาค่านี้ไปเทรนโมเดลแล้ววัดความคลาดเคลื่อน"
• y (ผลที่วัดได้) = 0.12 (ความคลาดเคลื่อน 12%) ← ตัวเลขเดียวที่ได้กลับมา
สังเกต: ทุกครั้งที่เปลี่ยน x ต้อง "เทรนใหม่ทั้งรอบ" เพื่อได้ y ใหม่ → การประเมิน 1 ครั้งแพงมาก (จะกลับมาเป็นแนวคิด "function evaluations" ในหัวข้อ 1.6)
💡 เทคนิคตีโจทย์ (เจอคำนี้ ตอบข้อนี้) เจอ "องค์ประกอบของปัญหา optimization มีอะไรบ้าง" → ตอบ Candidate solution (x), Objective function (f(x)), Evaluation cost (y) — จำสั้นๆ ว่า "X–F–Y: คำตอบ → เครื่องชิม → คะแนน" ระวังอย่าตอบสลับ: y คือ "ผลที่วัดได้" ไม่ใช่คำตอบที่เราหา

1.3 ปริภูมิค้นหา (Search Space — เซิร์ช สเปซ)

สัญชาตญาณ: search space = "แผนที่ของคำตอบที่เป็นไปได้ทุกจุด" เหมือนแผนที่เกมที่คุณเดินได้ทุกช่อง ถ้าปรับได้ 2 ค่า (อุณหภูมิ, เวลา) แผนที่คือพื้นราบ 2 มิติ ถ้าปรับได้ n ค่า ก็คือปริภูมิ n มิติ — อัลกอริทึม optimization ก็คือ "กลยุทธ์การเดิน" บนแผนที่นี้

🩵 ตัวอย่างจับมือทำ 1.3 — นับขนาดปริภูมิค้นหา โจทย์ (a): เครื่องผสมขนมมีปุ่ม 2 ปุ่ม แต่ละปุ่มหมุนได้ 5 ระดับ ปริภูมิค้นหามีคำตอบกี่คำตอบ?
• คำตอบ 1 ชุด = (ระดับปุ่ม A, ระดับปุ่ม B) เช่น (2, 4)
• ปุ่ม A เลือกได้ 5 แบบ × ปุ่ม B เลือกได้ 5 แบบ = $5 \times 5 = 25$ คำตอบ
โจทย์ (b): ถ้าแต่ละปุ่มปรับเป็น "ค่าต่อเนื่อง" ได้ทุกค่าในช่วง 0–1 (เช่น 0.371 ก็ได้)
• จำนวนคำตอบ = อนันต์ (นับไม่ถ้วน) — เราจึงต้องพึ่ง "กลยุทธ์การเดิน" ไม่ใช่การไล่ดูทีละจุด

1.4 พื้นผิวตอบสนอง (Response Surface — รีสปอนซ์ เซอร์เฟซ)

สัญชาตญาณ: เอาคะแนน $f(x)$ ของทุกจุดในปริภูมิค้นหา มา "วางเป็นความสูง" ซ้อนบนแผนที่ — จุดที่ f สูง = ภูเขา, จุดที่ f ต่ำ = หุบเขา ภูมิประเทศจำลองนี้คือ response surface (พื้นผิวตอบสนอง) เพราะมัน "ตอบสนอง" ต่อการเปลี่ยน x ด้วยการเปลี่ยนค่า f

⚠️ กับดักข้อสอบ — สองคำนี้ไม่เหมือนกัน! Search space = แผนที่ตำแหน่ง (มีแต่พิกัด x) / Response surface = แผนที่ตำแหน่ง + ความสูง f (ภูมิประเทศเต็มรูปแบบ) — ข้อสอบชอบสลับสองคำนี้ให้ตอบผิด

ประเด็นสำคัญ: ในโลกจริงเรา มองเห็น response surface ได้แค่จุดที่เราไปแตะเท่านั้น — เหมือนนักสำรวจเดินกลางหมอกหนา มีเทปวัดความสูง ยืนตรงไหนก็รู้แค่ความสูงจุดนั้น ไม่เห็นภูมิประเทศรอบตัว (จำไว้ มันจะเชื่อมกับ black-box ในหัวข้อ 1.9)

🩵 ตัวอย่างจับมือทำ 1.4 — วาด response surface เองจากฟังก์ชัน โจทย์: $f(x) = (x-2)^2$ บนช่วง $S=[0,4]$ — คำนวณความสูงทีละจุด:
• x = 0 → $f(0) = (0-2)^2 = 4$ (ยอดเขาซ้าย)
• x = 1 → $f(1) = (1-2)^2 = 1$
• x = 2 → $f(2) = 0$ ← ก้นหุบเขา (จุดต่ำสุด)
• x = 3 → $f(3) = 1$ / x = 4 → $f(4) = 4$ (ยอดเขาขวา)
อ่านผล: ถ้าวางแกนนอน = x และแกนตั้ง = f จะได้รูปตัว U คว่ำลง = หุบเขารูปถ้วย มีก้นที่ x = 2 — นี่คือ response surface ของปัญหานี้

1.5 คำสาปแห่งมิติ (Curse of Dimensionality — เคอส ออฟ ไดเมนชันนาลิตี้)

สัญชาตญาณ: สำรวจเส้นตรง 1 มิติ วางจุดห่างเท่าๆ กัน 10 จุดก็ครบ แต่ตาราง 2 มิติต้องใช้ $10 \times 10 = 100$ จุด ลูกบาศก์ 3 มิติต้อง $10^3 = 1{,}000$ จุด — ทุกครั้งที่เพิ่ม 1 มิติ จำนวนจุดโตขึ้น 10 เท่าเสมอ → n มิติต้องใช้ $10^n$ จุด ซึ่งโตแบบ exponential (เอ็กซ์โพเนนเชียล — ยกกำลัง) จนคอมพิวเตอร์ไหว

🩵 ตัวอย่างจับมือทำ 1.5 — รู้สึกถึง "คำสาป" ด้วยตัวเลขจริง โจทย์: สำรวจทุกจุดในตาราง โดยแต่ละมิติแบ่งเป็น 10 ระดับ และประเมิน 1 จุดใช้เวลา 1 มิลลิวินาที (0.001 วินาที) — ใช้เวลาเท่าไหร่เมื่อจำนวนมิติเพิ่ม?
• 1 มิติ: $10^1 = 10$ จุด → 10 มิลลิวินาที (แสนวินาที — จบทันที)
• 4 มิติ: $10^4 = 10{,}000$ จุด → 10,000 มิลลิวินาที = 10 วินาที
• 6 มิติ: $10^6 = 1{,}000{,}000$ จุด → $10^6$ มิลลิวินาที = $10^3$ วินาที ≈ 17 นาที
• 10 มิติ: $10^{10}$ จุด → $10^7$ วินาที ÷ 86,400 (วินาทีต่อวัน) ≈ 116 วัน!
• 13 มิติ: $10^{13}$ จุด → $10^{10}$ วินาที ≈ 317 ปี!
สรุป: เพิ่มมิติแค่หยิบมือ ปัญหาเปลี่ยนจาก "วินาที" เป็น "ปี" — นี่คือเหตุผลที่ต้องใช้อัลกอริทึมฉลาด ไม่ใช่ไล่ตรวจทุกจุด (brute force — บรูท ฟอร์ซ: ตรวจหมดทุกกรณี)
💡 เทคนิคตีโจทย์ เจอ "ทำไม optimization ในมิติสูงถึงยาก" → ตอบว่า จำนวนจุด/พื้นที่ที่ต้องสำรวจโตแบบยกกำลังตามจำนวนมิติ ($10^n$) ทำให้ข้อมูลเบาบางและไล่สำรวจทั้งหมดไม่ทัน — ห้ามตอบกว้างๆ ว่า "เพราะข้อมูลเยอะ"

1.6 วัดกันด้วยอะไร: Function Evaluations (ฟังก์ชัน อีวาลิวเอชันส์ — การเรียกใช้ฟังก์ชัน)

เวลาเทียบ "อัลกอริทึม A เก่งกว่า B ไหม" การจับเวลาเป็นวินาที ไม่ยุติธรรม เพราะผลขึ้นกับเครื่อง ภาษาโปรแกรม และฝีมือเขียนโค้ด สิ่งที่ยุติธรรมกว่าคือนับ จำนวนครั้งที่ต้องเรียกใช้ฟังก์ชันเป้าหมาย (function evaluations) — เพราะแต่ละครั้งอาจแพงมาก (เช่น รันจำลองโรงงาน 1 ครั้ง = 1 ชั่วโมง) และการ "นับครั้ง" ให้ตัวเลขเดียวกันไม่ว่ารันบนเครื่องไหน

Budget $B$ (บัดเจ็ต — งบประมาณ): เพดานจำนวน function evaluations ที่อนุญาต เช่น "ทุกอัลกอริทึมเรียก f ได้ 1,000 ครั้งเท่ากัน" — เป็นกติกามาตรฐานของการแข่งขันที่เป็นธรรม (จะใช้อีกทีในบทที่ 3)
🩵 ตัวอย่างจับมือทำ 1.6 — เทียบ 2 อัลกอริทึมแบบถูกวิธี โจทย์: อัลกอริทึม A รันเสร็จใน 5 วินาที ใช้การเรียก f 300 ครั้ง จบที่ค่า f = 0.05 / อัลกอริทึม B รันเสร็จใน 20 วินาที เรียก f 300 ครั้ง จบที่ค่า f = 0.02 — ใครดีกว่า?
ตอบ: งบเท่ากัน (300 ครั้ง) → เทียบ "คุณภาพคำตอบปลายทาง": B ได้ f = 0.02 ต่ำกว่า (ดีกว่า เพราะเรา minimize) → B ชนะ
ทำไมไม่ดูเวลา: เพราะถ้าเอา B ไปรันบนเครื่องเร็วกว่า อาจเสร็จใน 4 วินาที — เวลาเปลี่ยนได้ตามเครื่อง แต่ "จำนวนครั้งที่เรียก f" กับ "ค่า f ปลายทาง" ไม่เปลี่ยน → จึงเป็นไม้วัดที่เป็นธรรม

1.7 Global Optimum vs Local Optimum (โกลบอล ออพทิมัม vs โลคัล ออพทิมัม)

Global optimum $x^*$: จุดที่ $f(x^*) \le f(x)$ เทียบกับ $x$ ทุกจุดใน search space — "ต่ำสุดของทั้งประเทศ"
Local optimum: จุดที่ต่ำกว่า เพื่อนบ้านรอบๆ (บริเวณใกล้เคียงเท่านั้น) — "ต่ำสุดของหมู่บ้านตัวเอง"
สัญลักษณ์คืออะไร
$x^*$ ("เอ็กซ์-สตาร์")คำตอบที่ดีที่สุด (ดาว = "ฉลากคำตอบที่เราตามหา") — ถ้าเห็นดาวติดท้ายตัวแปรไหน แปลว่า "เวอร์ชันดีที่สุดของตัวนั้น"
$\le$ ("น้อยกว่าหรือเท่ากับ")ค่าฝั่งซ้ายต้องไม่มากกว่าฝั่งขวาจุดใดเลย
🩵 ตัวอย่างจับมือทำ 1.7 — หา local/global จากภูมิประเทศแบบตาราง (ไม่ต้องใช้แคลคูลัส) โจทย์: ปริภูมิค้นหามี 10 จุด (จุดที่ 1–10) ค่า f เรียงดังนี้:
[5, 3, 4, 6, 2, 3, 7, 4, 5, 6]
วิธีตรวจ (จุดไหนคือ local min? — เทียบกับเพื่อนบ้านซ้าย-ขวา):
• จุดที่ 2 (ค่า 3): เพื่อนบ้านคือ 5 (ซ้าย) และ 4 (ขวา) → 3 ต่ำกว่าทั้งคู่ → local minimum ✓
• จุดที่ 5 (ค่า 2): เพื่อนบ้านคือ 6 (ซ้าย) และ 3 (ขวา) → 2 ต่ำกว่าทั้งคู่ → local minimum ✓
• จุดที่ 8 (ค่า 4): เพื่อนบ้าน 7 กับ 5 → 4 ต่ำกว่าทั้งคู่ → local minimum ✓
เทียบทุก local กัน: ค่า 2 < 3 < 4 → จุดที่ 5 (ค่า 2) ต่ำสุดในบรรดาคำตอบทั้งหมด → global minimum
ข้อสรุปสำคัญ: local minimum มีได้หลายจุด (ตรงนี้ 3 จุด) แต่ global มีจุดเดียว — อัลกอริทึมที่เดินลงเขาอย่างเดียวอาจไปหยุดที่จุดที่ 2 หรือ 8 แล้วคิดว่า "จบแล้ว" ทั้งที่จุดที่ 5 ยังรออยู่
💡 เทคนิคตีโจทย์ เจอ "ต่ำสุดเมื่อเทียบกับจุดรอบๆ/เพื่อนบ้าน" → Local optimum / เจอ "ต่ำสุดในบรรดาคำตอบที่เป็นไปได้ทั้งหมด" → Global optimum — อ่าน "ขอบเขตการเทียบ" ให้ดี: รอบๆ = local, ทั้งหมด = global

1.8 การลู่เข้าก่อนกำหนด (Premature Convergence) และการเริ่มต้นใหม่แบบสุ่ม (Random Restarts)

สัญชาตญาณ: ทีมสำรวจ 50 คนลงเนินหาจุดต่ำสุด ทุกคนวิ่งตามกันเข้าหลุมแรกที่เจอแล้วยืนกอดกันอยู่ในนั้น ทั้งที่หลังเนินมีหลุมลึกกว่ารออยู่ — กลุ่ม "เสียความหลากหลาย" เร็วเกินไป สำรวจยังไม่ครบก็รวมตัวแล้ว

Premature convergence (พรีเมเจอร์ คอนเวอร์เจนซ์ — การลู่เข้าก่อนกำหนด): การที่อัลกอริทึม/กลุ่มคำตอบรวมตัวกันที่จุดเดียวเร็วเกินไป จนความหลากหลาย (diversity — ไดเวอร์ซิตี้) หายไป การสำรวจ (exploration — เอ็กซ์พลอเรชัน: ตะลุยหาพื้นที่ใหม่) จบก่อนกำหนด และมักจบที่ local optimum

ทางแก้พื้นฐาน: Random Restarts (แรนดอม รีสตาร์ท — เริ่มใหม่แบบสุ่ม)

best = ∞
for r = 1 … R:              # วิ่ง R รอบ แต่ละรอบ "อิสระ" จากกัน
    x = สุ่มจุดใน S          # เริ่มจากจุดสุ่ม ไม่เกี่ยวกับรอบก่อน
    x = local_search(x)     # เดินลงเขาจนติด local optimum
    best = min(best, f(x))  # จดสถิติดีที่สุดที่เคยเจอ
return best
🩵 ตัวอย่างจับมือทำ 1.8 — ทำไม "เริ่มใหม่หลายรอบ" ทำให้เจอคำตอบดีแทบแน่นอน โจทย์: สมมติ 1 รอบมีโอกาส 90% ที่จะไปจบในหลุมที่ดี ($p = 0.9$) — ถ้าเริ่มใหม่ 5 รอบ (อิสระจากกัน) โอกาสที่ "อย่างน้อย 1 รอบเจอหลุมดี" เท่าไหร่?
ขั้น 1: โอกาสที่ 1 รอบ "พลาด" = $1 - 0.9 = 0.1$
ขั้น 2: โอกาสที่ "พลาดทั้ง 5 รอบ" = คูณกันทีละรอบ (เพราะอิสระจากกัน) = $0.1^5 = 0.00001$
ขั้น 3: โอกาสที่ "ไม่พลาดหมด" (มีอย่างน้อย 1 รอบเจอ) = $1 - 0.00001 = 0.99999$ = 99.999%
อ่านผล: จาก 90% พุ่งเป็น 99.999% — ยิ่งเริ่มใหม่เยอะ โอกาส "ซวยทุกรอบ" ยิ่งเข้าใกล้ศูนย์ (แบบ $p^R$)
⚠️ จุดที่ข้อสอบชอบหลอก เงื่อนไขสำคัญของ restarts คือ ความเป็นอิสระ — ถ้า "เริ่มใหม่" แต่เริ่มใกล้ๆ จุดเดิมทุกครั้ง ก็ยังติดหลุมเดิม ไม่ใช่ restart ที่แท้จริง
💡 เทคนิคตีโจทย์ เจอ "เสียความหลากหลายเร็ว / รวมตัวที่จุดเดียวเร็วเกินไป" → ตอบ Premature convergence + ทางแก้พื้นฐานคือ Random restarts

1.9 การจำแนกตามความสามารถในการหาอนุพันธ์: Differentiable vs Black-box

คำถามแรกก่อนเลือกอัลกอริทึมเสมอ: "เรารู้จัก f แค่ไหน?"

ประเภทเรารู้อะไรต้องใช้วิธีไหนตัวอย่างจริง
Differentiable (ดิฟเฟอเรนเชียเบิล — หาอนุพันธ์ได้, บางทีเรียก white-box = กล่องขาว)รู้สูตร f ชัดเจน → หาความชัน $\nabla f$ นำทางได้วิธีที่ใช้เกรเดียนต์ (บทที่ 4)$f(x) = x^2 + 3x$; ค่า loss ของ neural network
Black-box (แบล็ก-บ็อกซ์ — กล่องดำ)ใส่ x ได้ y ออก เท่านั้น — ไม่มีสูตร ไม่มีอนุพันธ์วิธีสุ่ม/ไม่ใช้อนุพันธ์ (บทที่ 3)จูนค่าตั้งต้นของโมเดล (ต้องเทรนจริงถึงรู้ผล), จำลองโรงงาน, A/B test
🩵 ตัวอย่างจับมือทำ 1.9 — จำแนก 3 สถานการณ์ (โจทย์ข้อสอบชอบให้แบบนี้) สถานการณ์ (ก): $f(x) = 3x^2 + 2x$ → มีสูตรชัด หาอนุพันธ์ได้ ($f'(x) = 6x + 2$) → Differentiable
สถานการณ์ (ข): อยากรู้ว่าค่าตั้งต้นชุดไหนทำให้โมเดลแม่นสุด แต่ต้อง "เทรน 20 นาที" ทุกครั้งถึงจะรู้คะแนน → ไม่มีสูตรปิด (closed-form) ให้หาอนุพันธ์ → Black-box
สถานการณ์ (ค): ร้านค้าออนไลน์ลอง 2 แบบหน้าเว็บ (A/B test) แล้วดูยอดขาย → ได้แค่ตัวเลขผลจริง → Black-box
สรุปกฎง่ายๆ: ถ้าต้อง "รันจริง/ทดลองจริง" เพื่อได้ค่า = Black-box / ถ้ามีสูตรหาความชันได้ = Differentiable
⚠️ กับดัก "เขียนโปรแกรมคำนวณ f ได้" ≠ "หาอนุพันธ์ได้" — อนุพันธ์ต้องมาจากสูตรหรือเทคนิคพิเศษ (หัวข้อ 4.4) ไม่ใช่แค่ผลการรันโปรแกรม
💡 เทคนิคตีโจทย์ เจอ "เรียกใช้ f ได้อย่างเดียว / ไม่รู้สูตร / ไม่มีอนุพันธ์ / ต้องรันการจำลอง" → นี่คือ Black-box → ต้องใช้วิธีสุ่ม (บทที่ 3) — ห้ามตอบ Gradient Descent เด็ดขาด เพราะมันต้องใช้อนุพันธ์!

1.10 ทฤษฎี No Free Lunch (โน ฟรี ลันช์ — "ไม่มีมื้อฟรี") และการเชื่อมโยงกับ Machine Learning

ทฤษฎีบท No Free Lunch (NFL): ถ้าเอาผลงานของอัลกอริทึม optimization สองตัวอะไรก็ได้ มาเฉลี่ยกัน "เหนือปัญหาที่เป็นไปได้ทั้งหมด" ค่าเฉลี่ยจะเท่ากันพอดี — สรุปสั้นๆ: ไม่มีอัลกอริทึมใดชนะทุกปัญหา

สัญชาตญาณ — ทำไมถึง "ไม่มีเทพ": อัลกอริทึมที่ดูฉลาด จริงๆ คือการ "เดาโครงสร้าง" ของปัญหา (เดาว่า smooth — สมูท: เรียบต่อเนื่อง, เดาว่าคอนเวกซ์ ฯลฯ) เหมือนกุญแจที่เซาะร่องมาเป๊ะกับล็อกดอกนี้ — เปิดดอกนี้ลื่นไหล แต่เอาไปเปิดดอกอื่นไม่ได้เลย ทฤษฎีบอกว่า จำนวนปัญหาที่อัลกอริทึม A ชนะ = จำนวนปัญหาที่ A แพ้คืนพอดี

  • ผลสืบเนื่อง 1: ต้อง จับคู่ อัลกอริทึมกับโครงสร้างปัญหา (มีอนุพันธ์ → ใช้เกรเดียนต์ / black-box → ใช้วิธีสุ่ม)
  • ผลสืบเนื่อง 2: ต้อง ทดลองเทียบกันจริง บนปัญหาที่เราสนใจ (เป็นที่มาของหัวข้อ 3.7)
  • เชื่อมโยงกับ Machine Learning (แมชชีน เลิร์นนิง — การให้เครื่องเรียนรู้): หลักการเดียวกัน — ไม่มีโมเดลเดียวที่ดีที่สุดกับทุกชุดข้อมูล จึงต้องลองหลายโมเดล แล้วใช้ชุดตรวจสอบ (validation set — แวลิเดชัน เซ็ต: ข้อมูลไว้ตรวจคุณภาพโมเดล) เป็นผู้ตัดสิน
🩵 ตัวอย่างจับมือทำ 1.10 — ใช้ NFL ตอบสถานการณ์จริง สถานการณ์: เพื่อนอวดว่า "อัลกอริทึม X เทพสุด ชนะทุกโจทย์แน่นอน"
ตอบด้วย NFL: ไม่มีอัลกอริทึมใดชนะทุกปัญหา (นั่นคือตัวทฤษฎีบท) — ความเก่งของ X ต้องมาจากการ "เข้ากับโครงสร้างปัญหาประเภทหนึ่ง" พอดี ถ้าเอาไปใช้กับปัญหาโครงสร้างต่างออกไป อาจแย่กว่าวิธีธรรมดาก็ได้
สิ่งที่ควรทำแทน: (1) ดูว่าปัญหาเรามีอนุพันธ์ไหม (2) เลือกอัลกอริทึมที่เหมาะ (3) รันเทียบกันจริงด้วยงบเท่ากัน — อย่าเชื่อคำโฆษณา "เทพทุกงาน"
ในบริบท ML: เหมือนกัน — อย่าถาม "โมเดลไหนดีที่สุดในโลก" ให้ถาม "โมเดลไหนดีที่สุดสำหรับข้อมูลชุดนี้" แล้วพิสูจน์ด้วย validation
⚠️ อ่าน NFL ให้ขาด — ตีความผิดที่พบบ่อยสุด NFL ไม่ได้แปลว่า "บนปัญหาจริงทุกอัลกอริทึมเก่งเท่ากัน" — มันหมายถึงค่าเฉลี่ย "เหนือปัญหาทั้งหมดที่นึกออก" (รวมปัญหากวนโซ่ที่ไม่มีใครใช้จริง) บนปัญหาจริงที่มีโครงสร้างสวยงาม อัลกอริทึมที่เหมาะสมชนะขาด!
💡 เทคนิคตีโจทย์ เจอ "ผลของ No Free Lunch" → ตอบ 2 ข้อ: (1) ไม่มีอัลกอริทึมที่ดีที่สุดสำหรับทุกปัญหา (2) จึงต้องเลือกอัลกอริทึมให้เข้ากับโครงสร้างปัญหา และเทียบกันด้วยการทดลองจริง

Convex Optimization (คอนเวกซ์ ออพทิไมเซชัน — การหาค่าเหมาะสุดในโลก "นูน") — โลกอุดมคติที่ "หาเจอแน่นอน 100%"

2.1 ทำไมโลกต้องมี "คอนเวกซ์"

บทที่ 1 จบด้วยโศกนาฏกรรม local optimum (ติดหลุมตื้นทั้งที่มีหลุมลึกกว่า) — บทนี้คือโลกอุดมคติ: ปัญหามีหลุมเดียว ลาดลงอย่างเดียว ไม่มีกับดัก อัลกอริทึมง่ายๆ ก็ไหลลงถึงก้นแน่นอน และ local = global (หลุมที่ติด = หลุมที่ดีที่สุดเสมอ)

⚠️ กับดัก "คอนเวกซ์" ไม่ใช่แค่ "โค้ง" — ต้องโค้งขึ้นตลอดทั้งกราฟ (ชาม) ถ้ามีส่วนโค้งลง (โดม/ภูเขา) แม้แต่ช่วงเดียว = ไม่คอนเวกซ์ทันที

2.2 เซตคอนเวกซ์ (Convex Set) และผลรวมคอนเวกซ์ (Convex Combination)

สัญชาตญาณ: เซตคอนเวกซ์ = รูปทรง "ไม่มีรอยบุ๋ม" — เอายางรัดมาคลุมแล้วแนบสนิททั้งรูป (วงกลม, สี่เหลี่ยม = คอนเวกซ์ / รูปดาว, โดนัท = ไม่คอนเวกซ์ เพราะมีบุ๋มหรือรูตรงกลาง)

$$\text{เซต } C \text{ คอนเวกซ์} \iff \forall\, x_1, x_2 \in C,\ \forall\, \theta \in [0,1]:\ \theta x_1 + (1-\theta)x_2 \in C$$"ลากเส้นตรงระหว่างสองจุดในเซต เส้นนั้นต้องอยู่ในเซตทั้งเส้น ไม่หลุดออกนอกรูป"
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$\theta$ ("ธีต้า")สัดส่วนการผสม ค่าระหว่าง 0 ถึง 1: θ = 1 → ได้ $x_1$ เป๊ะ, θ = 0 → ได้ $x_2$ เป๊ะ, θ = 0.5 → กึ่งกลางพอดี — นึกว่า "ปริมาณน้ำผสมน้ำหวาน"
$\theta x_1 + (1-\theta)x_2$"จุดบนเส้นเชื่อม" ระหว่าง $x_1$ กับ $x_2$ — การเฉลี่ยถ่วงน้ำหนัก 2 จุด (น้ำหนักรวม = 1 พอดี)
$\in$ ("เป็นสมาชิกของ")"อยู่ใน" — จุดที่ผสมแล้วต้องยังอยู่ในเซต ไม่หลุดออกนอกรูป
$\forall$ ("สำหรับทุก")"ทุกกรณี" — เงื่อนไขต้องจริงกับจุดคู่ใดก็ได้ในเซต ไม่ใช่แค่บางคู่
$\iff$ ("ก็ต่อเมื่อ")สองข้างจริงพร้อมกันเสมอ — อ่านย้อนไปย้อนมาได้
Convex combination (ผลรวมคอนเวกซ์): การผสมหลายจุด: $\sum_i \theta_i x_i$ เมื่อ $\theta_i \ge 0$ ทุกตัว และ $\sum_i \theta_i = 1$ — คือเวอร์ชัน "หลายจุด" ของการหาจุดบนเส้นเชื่อม (น้ำหนักห้ามติดลบ และรวมกันได้ 1 เท่านั้น) — สัญลักษณ์ $\sum$ ("ซิกมา") แปลว่า "บวกกันทั้งชุด"
🩵 ตัวอย่างจับมือทำ 2.2 — คำนวณจุดผสม + ตรวจเซตคอนเวกซ์ (a) คำนวณจุดผสม: ให้ $x_1 = (2, 1)$, $x_2 = (6, 5)$, θ = 0.25 — จุดผสม z อยู่ที่ไหน?
• แทนสูตร: $z = 0.25\,x_1 + 0.75\,x_2$ (สังเกต: น้ำหนักตัวที่สอง = 1 − 0.25 = 0.75)
• พิกัดแกนแรก: $0.25 \times 2 + 0.75 \times 6 = 0.5 + 4.5 = 5$
• พิกัดแกนสอง: $0.25 \times 1 + 0.75 \times 5 = 0.25 + 3.75 = 4$
• สรุป: $z = (5, 4)$ — อยู่บนเส้นเชื่อมจาก $x_1$ ไป $x_2$ (เพราะ θ = 0.25 ใกล้ $x_2$ z เลยอยู่ใกล้ $x_2$)
(b) ตรวจว่ารูปทรงคอนเวกซ์ไหม: โดนัท (วงแหวน) — เลือกจุด 2 จุดบนขอบฝั่งตรงข้ามกัน ลากเส้นตรง → เส้นทะลุผ่าน "รูตรงกลาง" ซึ่งไม่ใช่สมาชิกเซต → ไม่คอนเวกซ์ ✓
💡 เทคนิคตีโจทย์ โจทย์ให้รูปทรงแล้วถาม "คอนเวกซ์ไหม?" → วิธีตายตัว: เลือกจุดสองจุดที่ สงสัยที่สุด (ริมบุ๋ม ขอบรู) ลากเส้นตรง ถ้าเส้นหลุดออกนอกรูปแม้คู่เดียว → ไม่คอนเวกซ์ทันที (หา 1 คู่ที่พังก็พอ ไม่ต้องเช็คทุกคู่)

2.3 ฟังก์ชันคอนเวกซ์ (Convex Function) และการทดสอบด้วยคอร์ด (Chord Test)

สัญชาตญาณ: วางไม้คาขอบชามซุปสองจุด (ไม้แท่งนั้น = chord / คอร์ด) — ไม้ต้องไม่จมใต้ผิวซุปเด็ดขาด ถ้าผิวซุปโผล่ทะลุเหนือไม้ตรงไหน = ไม่คอนเวกซ์ ทันที

$$f\big(\theta x_1 + (1-\theta)x_2\big) \;\le\; \theta f(x_1) + (1-\theta) f(x_2)$$"ผสมจุดก่อนแล้ววัด ≤ วัดก่อนแล้วผสม" — กราฟต้องอยู่ใต้เส้นคอร์ดเสมอ
ฝั่งของอสมการหมายความว่าอะไร
ซ้าย: $f(\theta x_1 + (1-\theta)x_2)$"ผสมจุดก่อนแล้ววัด" — เดินไปยืนที่จุดกลางบนเส้นเชื่อม แล้วดูความสูงกราฟจริง ณ จุดนั้น
ขวา: $\theta f(x_1) + (1-\theta)f(x_2)$"วัดก่อนแล้วผสม" — ความสูงของเส้นคอร์ด (ไม้) ตรงแนวเดียวกัน
🩵 ตัวอย่างจับมือทำ 2.3 — ใช้ Chord Test ทั้งของ "คอนเวกซ์" และ "ไม่คอนเวกซ์" (a) ทดสอบ $f(x) = x^2$ ที่ $x_1 = 1$, $x_2 = 3$, θ = 0.5:
• ฝั่งซ้าย (ผสมจุดก่อน): จุดผสม = $0.5(1) + 0.5(3) = 2$ → $f(2) = 4$
• ฝั่งขวา (วัดก่อนแล้วผสม): $0.5 f(1) + 0.5 f(3) = 0.5(1) + 0.5(9) = 5$
• เทียบ: $4 \le 5$ ✓ → ผ่าน → คอนเวกซ์
(b) ทดสอบ $f(x) = \sqrt{x}$ (รากที่สอง) ที่ $x_1 = 0$, $x_2 = 4$, θ = 0.5:
• ฝั่งซ้าย: จุดผสม = 2 → $f(2) = \sqrt{2} \approx 1.414$
• ฝั่งขวา: $0.5(0) + 0.5(2) = 1$
• เทียบ: $1.414 \le 1$? เท็จ! → กราฟโผล่เหนือไม้ → ไม่คอนเวกซ์ (จริงๆ มัน concave — คอนเคฟ: โค้งลงแบบโดม)
⚠️ จุดที่ข้อสอบชอบหลอก — ทิศของอสมการ $f(\text{ผสม}) \le \text{ผสมของ} f$ = คอนเวกซ์ (ชาม) ถ้าโจทย์เขียนกลับเป็น $\ge$ นั่นคือ concave (คอนเคฟ — โค้งลงแบบโดม) อย่าตอบสลับ! ตัวอย่างคู่ตรงข้ามที่เจอบ่อย: $\log x$ เป็น concave / $-\log x$ จึงคอนเวกซ์

2.4 อีพิกราฟ (Epigraph)

สัญชาตญาณ: หยิบกราฟ f ขึ้นมาแล้ว "เทสี" ทับทุกพื้นที่ที่อยู่ "บนหรือเหนือ" กราฟลงไป — พื้นที่ที่ถูกเททั้งหมด = epi f ("epi" มาจากภาษากรีกแปลว่า "เหนือ")

$$\text{epi}\, f = \{(x, t) : f(x) \le t\}$$
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$\{(x,t) : \dots\}$"เซตของจุด $(x,t)$ ทั้งหมดที่เงื่อนไขขวาจริง" — ปีกกาคือ "รวมทุกจุดที่ผ่านเกณฑ์"
$t$ ("ที")พิกัดความสูง — นึกว่า "ปักธง" ที่ความสูง t เหนือตำแหน่ง x ถ้าธง "ไม่จมใต้กราฟ" (t ≥ f(x)) จุดนั้นอยู่ใน epi f
epi f ("อีพิ-เอฟ")ภูมิภาคเหนือกราฟทั้งหมด — จุด $(x, t)$ หนึ่งจุด = "ยืนที่แกนนอนตำแหน่ง x และแกนตั้งสูง t"
ทฤษฎีบทสะพานเชื่อม (ออกสอบ!): $f$ เป็นฟังก์ชันคอนเวกซ์ $\iff$ epi $f$ เป็นเซตคอนเวกซ์ — แปลคุณสมบัติ "ฟังก์ชัน" ให้เป็นคุณสมบัติ "เซต" (จำสั้นๆ: "ชามซุป → ปริมาตรเหนือชามเป็นทรงนูนไม่มีบุ๋ม") — ทำให้ solver (โซลเวอร์: โปรแกรมแก้ปัญหา) ใช้เรขาคณิตของเซตจัดการได้
🩵 ตัวอย่างจับมือทำ 2.4 — จุดไหนอยู่ใน epi f? โจทย์: $f(x) = x^2$ — จุด $(3, 8)$ และ $(3, 9.5)$ จุดไหนอยู่ใน epi f?
วิธี: แทนค่าเงื่อนไข $f(x) \le t$ ทีละจุด
• จุด $(3, 8)$: $f(3) = 9$ → เช็ค $9 \le 8$? เท็จ → ธงสูง 8 "จมใต้กราฟ" (กราฟสูง 9) → ไม่อยู่ใน epi f
• จุด $(3, 9.5)$: $f(3) = 9$ → เช็ค $9 \le 9.5$? จริง → ธงลอยเหนือกราฟ → อยู่ใน epi f ✓
ข้อสังเกต: จุดตัดกับกราฟพอดี เช่น $(3, 9)$: $9 \le 9$ จริง (มีเครื่องหมายเท่ากับ) → อยู่ใน epi f ด้วย
💡 เทคนิคตีโจทย์ เจอ "จงแสดงว่า f คอนเวกซ์โดยพิจารณา epi f" → ขั้นตอน: หยิบจุดสองจุดใน epi f (คือ $(x_1,t_1)$ ที่ $t_1 \ge f(x_1)$ ฯลฯ) → ผสมด้วย θ → ใช้นิยามความคอนเวกซ์ของ f ชี้ว่าจุดผสมก็ยัง $f(x) \le t$ อยู่ → จบ

2.5 การตรวจสอบความคอนเวกซ์: เงื่อนไขอันดับ 1 และอันดับ 2

อันดับ 1 — ระนาบสัมผัสอยู่ใต้กราฟเสมอ (First-order Condition — เฟิร์สต์ ออร์เดอร์ คอนดิชัน)

$$f(x_2) \;\ge\; f(x_1) + \nabla f(x_1)^\top (x_2 - x_1) \quad \text{สำหรับทุก } x_1, x_2$$ฝั่งขวา = ค่าที่ "ระนาบสัมผัส" (tangent plane) พยากรณ์ — กราฟจริงต้องสูงกว่าหรือเท่ากันเสมอ
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$\nabla f(x_1)$ ("เกรเดียนต์ เอฟ")เวกเตอร์ "ความชัน" ของกราฟที่จุด $x_1$ — บอกว่าถ้าก้าวเล็กๆ ไปทางไหน f จะขึ้น/ลงแค่ไหน (บทที่ 4 จะเจาะลึก — ตอนนี้รู้แค่ว่ามันคือ "ความชันหลายมิติ" ก็พอ)
$(x_2 - x_1)$เวกเตอร์ "ทิศทางเดิน" จากจุด $x_1$ ไปจุด $x_2$ (ลบกัน = ชี้จากหลังไปหน้า)
$\nabla f(x_1)^\top(x_2-x_1)$ผลคูณจุด (dot product — ด็อท โปรดัคต์: คูณสองเวกเตอร์ได้ตัวเลขเดียว) = "ความชัน × ระยะเดิน" = การประมาณค่า f ด้วยเส้นตรง เหมือนสูตร $a + b \cdot \Delta x$ ที่คุ้นเคย

สัญชาตญาณ: แตะแผ่นกระดานแบนที่จุดใดจุดหนึ่งของชามซุป — แผ่นจะวางพาด "ใต้" ชามทั้งใบเสมอ ไม่มีทางตัดทะลุชาม ถ้าแผ่นสัมผัสโผล่เหนือกราฟจุดไหน = ไม่คอนเวกซ์

อันดับ 2 — เมทริกซ์เฮสเซียนกึ่งบวกแน่นอน (Second-order Condition)

$$f \text{ คอนเวกซ์} \iff \nabla^2 f(x) \succeq 0 \quad \text{ทุกจุด } x$$
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$\nabla^2 f$ ("เกรเดียนต์สอง / เฮสเซียน")เมทริกซ์ของอนุพันธ์อันดับสอง = เครื่องวัดความโค้ง — ใน 1 มิติมันคือ $f''$ (อนุพันธ์สอง) ธรรมดา; ช่องทแยง = ความโค้งรายแกน, ช่องนอกทแยง = ความโค้งไขว้ระหว่างแกน
$\succeq 0$ ("กึ่งบวกแน่นอน", PSD)"โค้งขึ้นในทุกทิศทาง" — ไม่มีทิศไหนที่ความโค้งติดลบ; ตรวจได้ด้วย $v^\top H v \ge 0$ ทุกเวกเตอร์ $v$ หรือดู eigenvalue ทุกตัว $\ge 0$
$v^\top H v$ ("วี ทรานสโพส เอช วี")ความโค้งที่วัดได้เมื่อ "เดินไปทิศ v" — สรุปทั้งทิศให้เหลือตัวเลขเดียว: ≥ 0 = โค้งขึ้น, < 0 = โค้งลง (มีบุ๋ม!)
eigenvalue ("ไอเกนวาลู — ค่าเอกเทศ")ความโค้งตาม "แกนหลัก" ของเมทริกซ์ — ถ้าทุกตัวไม่ติดลบ = โค้งขึ้นทุกแกน = ชามจริง
🩵 ตัวอย่างจับมือทำ 2.5 — ตรวจความคอนเวกซ์ด้วยเฮสเซียน (ทีละบรรทัด เหมือนครูนั่งข้างๆ) โจทย์: $f(x, y) = x^2 + 2xy + 2y^2$ คอนเวกซ์หรือไม่?
ขั้น 1 — หาอนุพันธ์ย่อยอันดับ 1 (partial derivative — พาร์เชียล: หาความชันโดยถือตัวแปรอื่นนิ่ง): $\dfrac{\partial f}{\partial x} = 2x + 2y$, $\dfrac{\partial f}{\partial y} = 2x + 4y$
ขั้น 2 — หาเฮสเซียน (อนุพันธ์อีกที แล้วจัดเป็นเมทริกซ์ 2×2): $\nabla^2 f = \begin{bmatrix} 2 & 2 \\ 2 & 4 \end{bmatrix}$
ขั้น 3 — หา eigenvalues: ใช้สูตร $\lambda^2 - (\text{ผลรวมทแยง})\lambda + (\text{ดีเทอร์มิแนนต์}) = 0$
• ผลรวมทแยง (trace) = $2 + 4 = 6$ / ดีเทอร์มิแนนต์ (det) = $(2)(4) - (2)(2) = 4$
• สมการ: $\lambda^2 - 6\lambda + 4 = 0$ → $\lambda = \dfrac{6 \pm \sqrt{36 - 16}}{2} = \dfrac{6 \pm \sqrt{20}}{2}$
• $\lambda_1 \approx 5.24$ และ $\lambda_2 \approx 0.76$ — ทั้งคู่เป็นบวก
ขั้น 4 — สรุป: eigenvalues ≥ 0 ทุกตัว → $\nabla^2 f \succeq 0$ → คอนเวกซ์ ✓ (โครงเรื่องคือ: ชัน → โค้ง → เช็คว่าโค้งไม่ลงในทิศใดเลย)
(เทียบกับ 1 มิติเพื่อความเข้าใจ:) $f(x)=x^3$: $f''(x) = 6x$ — ที่ x < 0 ค่าติดลบ (โค้งลง) → ไม่คอนเวกซ์บน $\mathbb{R}$ ทั้งโดเมน
⚠️ ตัวอย่างโดนหลอก (จำให้ขึ้นใจ) $f(x,y) = x^2 - y^2$: เฮสเซียน $= \begin{bmatrix} 2 & 0 \\ 0 & -2 \end{bmatrix}$ → eigenvalue −2 < 0 → ไม่คอนเวกซ์ (ผิวอานม้า: โค้งลงทาง y แต่โค้งขึ้นทาง x) — และกับดักคลาสสิกอีกอย่าง: $f'' \ge 0$ ที่จุดเดียวไม่พอ! ต้อง PSD ทุกจุดในโดเมน
💡 เทคนิคตีโจทย์ โจทย์ "พิสูจน์/ตรวจความคอนเวกซ์" → เลือกแผน: (ก) หาเฮสเซียน → ชี้ PSD (ดีสุดกับฟังก์ชันกำลังสอง/พอลิโนเมียล) (ข) ใช้ composition rules หัวข้อถัดไป (ดีสุดกับ exp/log/max)

2.6 กฎการประกอบฟังก์ชัน (Composition Rules — คอมโพซิชัน รูลส์) ที่ใช้จริง

แทนที่จะคำนวณเฮสเซียนทุกครั้ง เรา "ต่อเลโก้" — ประกอบฟังก์ชันคอนเวกซ์จากชิ้นส่วนสำเร็จรูป ตามกฎที่พิสูจน์ไว้แล้ว:

กฎ (เงื่อนไข)ตัวอย่างที่ใช้ได้ทันที
ผลรวมถ่วงน้ำหนัก (น้ำหนัก ≥ 0) ของฟังก์ชันคอนเวกซ์ → คอนเวกซ์$f(x) = x^2 + 3e^x$ ✓
ฟังก์ชันแอฟฟิน $a^\top x + b$ → คอนเวกซ์ (และ concave พร้อมกัน)$2x + 1$, $3x - 2y + 5$ ✓
$g$ คอนเวกซ์ → $g(Ax + b)$ คอนเวกซ์ (ยัดแอฟฟินเข้าหน้า)$\|Ax + b\|$ ✓
$g$ คอนเวกซ์ + $h$ คอนเวกซ์และไม่ลด (nondecreasing) → $h(g(x))$ คอนเวกซ์$e^{x^2}$ (ชั้นใน $x^2$ คอนเวกซ์, exp คอนเวกซ์และไม่ลด) ✓
$g$ concave + $h$ คอนเวกซ์และไม่เพิ่ม (nonincreasing) → $h(g(x))$ คอนเวกซ์$-\log x$ ($\log$ concave แล้วเติมลบ) ✓
max ของฟังก์ชันคอนเวกซ์หลายตัว → คอนเวกซ์$\max(x^2, e^x)$ ✓
Norm (นอร์ม — ฟังก์ชันวัดความยาว) ใดๆ $\|\cdot\|$ → คอนเวกซ์$\|x\|_2$, $\|x\|_1$ ✓
🩵 ตัวอย่างจับมือทำ 2.6 — แยกชั้นแล้วอ้างกฎ (เร็วกว่าคิดเฮสเซียนมาก) โจทย์: $f(x) = e^{x^2}$ คอนเวกซ์ไหม?
ขั้น 1 — แยกชั้นใน/ชั้นนอก: ชั้นใน $g(x) = x^2$ / ชั้นนอก $h(u) = e^u$
ขั้น 2 — เช็คชั้นใน: $g'' = 2 \ge 0$ → คอนเวกซ์ ✓
ขั้น 3 — เช็คชั้นนอก: $h'' = e^u > 0$ → คอนเวกซ์ ✓ และ $h$ "ไม่ลด" (exp โตขึ้นเสมอ) ✓
ขั้น 4 — อ้างกฎ: "ชั้นในคอนเวกซ์ + ชั้นนอกคอนเวกซ์และไม่ลด" → $e^{x^2}$ คอนเวกซ์ ✓ (จบโดยไม่ต้องจิ้มเฮสเซียน)
(ตัวอย่างที่กฎใช้ไม่ได้:) $f(x) = e^{-x^2}$ — ชั้นใน $-x^2$ ไม่คอนเวกซ์ (โค้งลง) → กฎพัง ห้ามอ้าง (และจริงๆ ฟังก์ชันนี้ไม่คอนเวกซ์ — มันเป็น "กระดิ่ง" โค้งลงที่กลาง)
⚠️ กับดัก เงื่อนไข "nondecreasing/nonincreasing" ไม่ใช่ของแต่ง ต้องเช็คครบ 3 อย่างทุกครั้ง: ชั้นใน → ชั้นนอก → ทิศ monotone (โมโนโทน: เพิ่ม/ลดทางเดียว) — ข้ามข้อใดข้อหนึ่ง = อ้างกฎผิด = ตกข้อสอบ

2.7 รูปแบบมาตรฐานของปัญหาคอนเวกซ์ (3 เงื่อนไข — ออกสอบแน่นอน)

$$\min_x\ f_0(x) \quad \text{subject to} \quad f_i(x) \le 0,\ i = 1,\dots,m \qquad h_j(x) = 0,\ j = 1,\dots,p$$
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$f_0$ ("เอฟ-ซีโร่")Objective — สิ่งที่ต้องการ "ทำให้ต่ำสุด" (เช่น ต้นทุน, ความผิดพลาด)
$f_i(x) \le 0$ข้อจำกัดแบบอสมการ (inequality constraint) — "กำแพง" ที่คำตอบห้ามล้ำ เขียนมาตรฐานให้อยู่รูป ≤ 0 เสมอ
$h_j(x) = 0$ข้อจำกัดแบบสมการ (equality constraint) — "ราง" ที่คำตอบต้องวิ่งตามเป๊ะๆ
subject to ("ซับเจ็กต์ ทู" — s.t.)"โดยมีเงื่อนไขว่า" — คำตอบต้องผ่านข้อจำกัดทุกข้อจึงนับเป็น feasible (ทำได้จริง)
$i = 1,\dots,m$ / $j = 1,\dots,p$มีข้อจำกัดแบบอสมการ m ข้อ และแบบสมการ p ข้อ (ตัวเลขนับเริ่มจาก 1 ถึง m และ 1 ถึง p)
ปัญหาเป็น "ปัญหาคอนเวกซ์" ก็ต่อเมื่อครบ 3 เงื่อนไข (จำเป็น!):
1. $f_0$ (objective) เป็นฟังก์ชันคอนเวกซ์
2. $f_i$ ทุกตัว (ข้อจำกัดแบบอสมการในรูป $f_i(x) \le 0$) เป็นฟังก์ชันคอนเวกซ์
3. $h_j$ ทุกตัว (ข้อจำกัดแบบสมการ) เป็นแอฟฟินเท่านั้น ($h_j(x) = a^\top x + b$ — เชิงเส้นบวกค่าคงที่)

ทำไม $h_j$ ต้องแอฟฟิน "เท่านั้น" (ฟังก์ชันโค้งก็มี = 0 ได้นี่?): เพราะเซตของคำตอบที่ทำให้ฟังก์ชันโค้งเท่ากับศูนย์ มักไม่คอนเวกซ์ — ตัวอย่าง: $x^2 - 1 = 0$ มีคำตอบแค่ $\{1, -1\}$ สองจุดโดดๆ ลากเส้นจาก −1 ไป 1 ต้องผ่านจุด 0 (ซึ่งผิดเงื่อนไข) → เซตคำตอบไม่คอนเวกซ์ ระบบพังทันที ส่วนแอฟฟิน $a^\top x + b = 0$ ให้เส้นตรง/ระนาบ ซึ่งคอนเวกซ์เสมอ

ทำไม 3 เงื่อนไขนี้ทำให้พื้นที่คำตอบที่ผ่าน (feasible set) คอนเวกซ์: เซต $\{f_i \le 0\}$ = พื้นที่ "ใต้" ฟังก์ชันคอนเวกซ์ → คอนเวกซ์ / เซต $\{h_j = 0\}$ แอฟฟิน = เส้นตรง/ระนาบ → คอนเวกซ์ / และ จุดตัด (intersection — อินเทอร์เซกชัน: ส่วนที่ซ้อนกัน) ของเซตคอนเวกซ์ = คอนเวกซ์เสมอ

🩵 ตัวอย่างจับมือทำ 2.7 — จัดรูปปัญหาเข้ามาตรฐาน + ตรวจ 3 เงื่อนไข โจทย์: $\min\ x^2 + y^2$ เมื่อ $x + y \ge 2$ — เป็นปัญหาคอนเวกซ์ไหม?
ขั้น 1 — จัดข้อจำกัดให้อยู่รูป ≤ 0: ตอนนี้เป็นหัว $\ge$ (กลับด้าน) → ย้ายข้างแล้วคูณ −1: $-x - y + 2 \le 0$ ✓ (เครื่องหมายพลิกเพราะคูณลบ)
ขั้น 2 — ตรวจเงื่อนไขที่ 1: $f_0 = x^2 + y^2$ → เฮสเซียน = เมทริกซ์เอกลักษณ์ (diag 2,2) → PSD ✓ คอนเวกซ์
ขั้น 3 — ตรวจเงื่อนไขที่ 2: $f_1 = -x - y + 2$ เป็นแอฟฟิน → แอฟฟินคอนเวกซ์อัตโนมัติ ✓
ขั้น 4 — ตรวจเงื่อนไขที่ 3: ไม่มีข้อจำกัดแบบสมการ → ผ่านโดยดีฟอลต์ ✓
สรุป: ครบ 3 เงื่อนไข → เป็นปัญหาคอนเวกซ์ → local ที่เจอ = global ทันที
(ตัวอย่างที่ไม่ผ่าน:) ถ้าข้อจำกัดเป็น $x^2 + y^2 = 1$ (วงกลม) — แบบสมการแต่ "ไม่แอฟฟิน" → ไม่ใช่ปัญหาคอนเวกซ์ตามรูปแบบ (คำตอบบนวงกลมไม่ใช่เซตคอนเวกซ์)
⚠️ จุดที่ข้อสอบชอบหลอก (1) ข้อจำกัดแบบสมการที่ไม่แอฟฟิน เช่น $x^2 = 1$ — ห้ามใช้เด็ดขาด แม้ดู "เรียบร้อย" (2) อสมการ $\ge$ ต้องคูณ −1 ให้เป็น $\le 0$ ก่อนแล้วเช็คฝั่งที่เหลือ — หลายคนลืมคูณลบ เลยตัดสินความคอนเวกซ์ผิดทิศ
💡 เทคนิคตีโจทย์ เจอ "จัดให้อยู่ในรูปมาตรฐาน / ปัญหานี้คอนเวกซ์หรือไม่" → ขั้นตอนตายตัว 4 ขั้น: ย้ายข้างให้เป็น $\dots \le 0$ → เช็ค $f_0$ คอนเวกซ์ → เช็ค $f_i$ คอนเวกซ์ → เช็ค $h_j$ แอฟฟินเท่านั้น → สรุปทีละข้อ

2.8 ทฤษฎีบทหลัก: Local Optimum = Global Optimum

ทฤษฎีบท: ในปัญหาคอนเวกซ์ local minimum ทุกจุดคือ global minimum — "หลุมที่ต่ำสุดในย่านตัวเอง = หลุมต่ำสุดของทั้งประเทศ" (นี่คือเหตุผลที่คอนเวกซ์คือโลกอุดมคติ)
🩵 ตัวอย่างจับมือทำ 2.8 — พิสูจน์ด้วยการขัดแย้ง (reductio ad absurdum) ทีละบรรทัด แนวคิด: สมมติว่าทฤษฎีบทผิด → ไล่ตรรกะจนได้สิ่งที่ขัดแย้งกับนิยาม → แสดงว่าสมมติฐานผิด
สมมติ: $x_{local}$ เป็น local minimum แต่มีจุดที่ดีกว่า $x_b$ อยู่ไกลๆ โดย $f(x_b) < f(x_{local})$
ขั้น 1: สร้างจุดผสม $z = (1-\theta)x_{local} + \theta x_b$ โดยให้ θ เล็กมาก (เช่น 0.01) → z คือ "ก้าวเล็กๆ" จาก $x_{local}$ ไปทาง $x_b$ → z อยู่ในย่านใกล้เคียงของ local พอดี
ขั้น 2: feasible set คอนเวกซ์ → เส้นเชื่อมอยู่ในเซต → z ยัง feasible ✓
ขั้น 3: ใช้ความคอนเวกซ์ของ f: $f(z) \le (1-\theta)f(x_{local}) + \theta f(x_b)$ — แล้วเพราะ $f(x_b) < f(x_{local})$ การเฉลี่ยเข้ามาเลยทำให้ $f(z) < f(x_{local})$ (เหมือนเฉลี่ยคะแนน 80 กับ 90 ต้องได้ระหว่าง 80–90 แต่น้ำหนักไปทางต่ำกว่า)
ขั้น 4: เราได้จุด z "ในย่านเดียวกัน" ที่ต่ำกว่า $x_{local}$ → ขัดแย้งกับนิยาม local minimum! → สมมติฐานผิด → ไม่มีจุดที่ดีกว่าอยู่ที่ใดเลย → $x_{local}$ คือ global □ (สี่เหลี่ยม = จบการพิสูจน์)

ทำไมทฤษฎีบทนี้ยอดเยี่ยม: มันเปลี่ยนคำถามที่ตอบไม่ได้ ("จุดนี้ดีที่สุดในจักรวาลไหม? — ต้องมองทั้งประเทศ!") ให้เหลือคำถามง่าย ("จุดนี้ดีที่สุดแถวนี้ไหม? — มองแค่รอบตัว") — อัลกอริทึมลงเขาอะไรก็ได้ที่หา local เจอ = ได้ global ทันที นี่คือเหตุผลที่ Gradient Descent (บทที่ 4) มั่นใจได้บนปัญหาคอนเวกซ์

💡 เทคนิคตีโจทย์ เห็นประโยค "ปัญหานี้เป็นคอนเวกซ์ ดังนั้น …" → ตอบ 2 ประโยค: (1) local optimum ใดๆ = global optimum (2) อัลกอริทึมเชิงเกรเดียนต์จึงรับประกันว่าเจอคำตอบดีที่สุด ไม่มีกับดักหลุมพราง

2.9 เงื่อนไขความเหมาะที่สุดเมื่อมีข้อจำกัด (Optimality with Constraints)

  • ไม่มีข้อจำกัด: จุดเหมาะสุดต้อง $\nabla f(x^*) = 0$ — "จุดราบ" ความชันเป็นศูนย์ทุกทิศ (ยืนก้นหุบแล้วลาดไม่ลงทั้งซ้ายขวา)
  • มีข้อจำกัด: จุดดีที่สุดอาจอยู่ "ติดกำแพง" — อยากเดินลงต่อแต่ข้อจำกัดกั้นไว้ เลยหยุดแนบกำแพง
🩵 ตัวอย่างจับมือทำ 2.9 — เหมือนกันแต่ต่างกัน เพียงเพราะมี "กำแพง" โจทย์: $\min\ x^2$ เมื่อ $x \ge 1$
(a) ลองแบบไม่มีข้อจำกัดก่อน: $\nabla f = 2x = 0 \Rightarrow x^* = 0$ — แต่ $0 < 1$ ละเมิดข้อจำกัด! ใช้ไม่ได้ ทิ้ง
(b) หาคำตอบที่มีข้อจำกัด: ในโซนที่อนุญาต (x ≥ 1) ฟังก์ชัน $x^2$ ยิ่ง x น้อยยิ่งต่ำ → ดีที่สุดคือ "ต่ำที่สุดเท่าที่กฎอนุญาต" = $x^* = 1$ (แนบกำแพงพอดี) ได้ $f(1) = 1$
ตรวจด้วยเกรเดียนต์: ที่ x = 1, $\nabla f = 2 \ne 0$ — ชี้ทางลง (ไปทาง x ต่ำกว่า) แต่ทางนั้นเป็น "เขตห้าม" → ยืนแนบกำแพงนี่แหละถูกต้อง
แนวคิด KKT (เคเคที — เงื่อนไข Karush–Kuhn–Tucker) แบบภาพรวม: ที่จุดเหมาะสุด เกรเดียนต์ของ objective ต้อง "สมดุลกับแรงดันของกำแพง" (เกรเดียนต์ของข้อจำกัดที่แอคทีฟ) — แรงดึงลง = แรงกำแพงดันกลับ และในปัญหาคอนเวกซ์ เงื่อนไข KKT เป็นทั้งจำเป็นและเพียงพอ (เจอจุดที่ KKT อยู่ = เจอ global ทันที)
⚠️ จุดที่ข้อสอบชอบหลอก เห็น optimum ติดขอบข้อจำกัดแล้ว $\nabla f \ne 0$ อย่าตกใจว่า "ผิดทฤษฎี" — เงื่อนไข $\nabla f = 0$ ใช้ได้เฉพาะ "ไม่มีข้อจำกัด" เท่านั้น พอมีกำแพง optimum ติดกำแพงและ $\nabla f$ ไม่จำเป็นต้องเป็นศูนย์

3.1 เมื่อไม่มีอนุพันธ์ — กลับไป "เดินสำรวจ" ด้วยการเรียก f

จากบทที่ 1: ปัญหา black-box (แบล็ก-บ็อกซ์ — กล่องดำ: ใส่คำตอบได้คะแนนออก แต่ไม่รู้สูตรข้างใน) ให้เราทำอะไรไม่ได้นอกจาก (1) เลือกว่าจะลองจุดไหนต่อไป และ (2) ใช้ผลคะแนนที่ได้นำทาง — บทนี้คือคู่มือการเดินสำรวจเมื่อเรา "ตาบอด" ไม่เห็นความชัน มีแต่เทปวัดความสูง (ค่า f) ที่จุดที่ยืนเท่านั้น

3.2 Grid Search vs Random Search — ทำไม "การสุ่ม" ชนะในมิติสูง

  • Grid search (กริด เซิร์ช — ค้นแบบตาราง): วางจุดทดลองเป็นตารางช่องสม่ำเสมอทุกมิติ — ดูเรียบร้อยแต่มี 2 ปัญหา: (1) เจอ curse of dimensionality (คำสาปแห่งมิติ — จำนวนจุดโต $10^n$ จากบทที่ 1) และ (2) สิ้นเปลือง เพราะไล่ค่าซ้ำๆ ในมิติที่ "ไม่สำคัญ" โดยไม่จำเป็น
  • Random search (แรนดอม เซิร์ช — ค้นแบบสุ่ม): สุ่มจุดกระจายไปมา — ด้วยงบจำนวนจุดเท่ากัน แต่ละจุดจะมีค่า ไม่ซ้ำกัน ในทุกมิติ (โอกาสสุ่มซ้ำเป๊ะเกือบเป็นศูนย์) จึง "เจาะ" ค่าหลากหลายได้แม้กระทั่งมิติที่สำคัญ
ข้อค้นพบ Bergstra & Bengio (เบิร์กสตรา แอนด์ เบนจิโอ — งานวิจัยปี 2012): ปัญหาจูน hyperparameter จริงใน Machine Learning มักมี ไม่กี่มิติที่สำคัญจริงๆ — ด้วยงบเท่ากัน random search เจอโซนคำตอบดีได้ดีกว่า grid เพราะได้ค่าไม่ซ้ำหลากหลายในมิติสำคัญ และยังขนานกันได้ง่าย (แต่ละจุดทดลองไม่ต้องรอผลกัน)
🩵 ตัวอย่างจับมือทำ 3.2 — นับ "การทดลองที่มีคุณค่า" ของทั้งสองวิธี โจทย์: งบ 25 การทดลอง มี 2 ไฮเปอร์พารามิเตอร์ คือ (learning rate — เลิร์นนิง เรต: อัตราการเรียนรู้, batch size — แบตช์ ไซซ์: ขนาดชุดข้อมูลต่อรอบ) ปรากฏว่า ผลลัพธ์ขึ้นกับ learning rate เป็นหลัก ส่วน batch size ตั้งเท่าไหร่ผลแทบไม่ต่าง
(a) ถ้าใช้ Grid 5×5 (ตาราง 5 ค่า × 5 ค่า):
• learning rate ถูกไล่แค่ 5 ค่า เท่านั้น (เช่น 0.001, 0.01, 0.1, 1, 10) — แต่ละค่าถูกทดซ้ำ 5 ครั้ง (คู่กับ batch 5 ค่า)
• การทดลองที่ "ให้ข้อมูลใหม่จริงๆ" = แค่ 5 จาก 25 → เสียงบ 80% ไปกับความซ้ำซาก
(b) ถ้าใช้ Random 25 จุด:
• learning rate ถูกสุ่มได้ 25 ค่าแทบไม่ซ้ำกันเลย (เช่น 0.0037, 0.0512, 0.23, …) → การทดลองมีคุณค่าทั้ง 25
สรุป: งบเท่ากัน แต่ random สำรวจ "5 เท่า" ของค่าที่แตกต่างในมิติสำคัญ → โอกาสเจอโซนดีมากกว่า — นี่คือเหตุผลที่ Bergstra & Bengio สรุปว่า random ชนะในมิติสูง
💡 เทคนิคตีโจทย์ คำถาม "ทำไม random search ชนะ grid ด้วยงบเท่ากัน" → ตอบ 3 ข้อ: (1) ได้ค่าตัวอย่างที่ไม่ซ้ำมากกว่าต่อมิติ (2) โดยเฉพาะเมื่อมีเพียงบางมิติสำคัญจริง (Bergstra & Bengio) (3) ทำงานขนานได้ง่าย — ห้ามตอบแค่ "สุ่มแล้วดูเหมือนครอบคลุมกว่า" ต้องมีเหตุผลเรื่อง "ค่าซ้ำในมิติไม่สำคัญ"

3.3 Stochastic Hill Climbing (สโตแคสติก ฮิลล์ ไคลม์บิง — การไต่เนินแบบสุ่ม)

สัญชาตญาณ: ปีนเขากลางหมอกหนา — คุณรู้แค่ความสูง "จุดที่ยืนอยู่" เท่านั้น (เพราะกลางหมอกมองไม่เห็นรอบตัว) จึงทำได้แค่ "เหยียบลอง" ทิศสุ่มหนึ่งก้าว ถ้าจุดใหม่ "ต่ำกว่า" (ดีกว่า) ก็ย้ายไป ถ้าแย่กว่าก็ถอยกลับมายืนเดิม แล้วเหยียบลองใหม่ — ทำซ้ำจนหมดงบ

x = จุดสุ่มเริ่มต้นใน S
while ยังเหลือ budget (จำนวนเรียก f):
    x' = x + ก้าวสุ่ม            # สุ่มทั้งทิศทางและระยะ
    if f(x') < f(x):            # กฎยอมรับ: ดีขึ้นเท่านั้น!
        x = x'                  # ยอมรับ → ย้ายไปยืนจุดใหม่
    # ถ้าแย่ลงหรือเท่าเดิม → ปฏิเสธ อยู่ที่เดิม แล้วสุ่มก้าวใหม่
return จุดที่ดีที่สุดเท่าที่เคยเจอ
กฎการยอมรับ "เฉพาะคำตอบที่ดีขึ้น" (accept only if better): อัลกอริทึมนี้เป็น pure exploitation (พิวร์ เอ็กซ์พลอยเทชัน — เก็บเกี่ยวจากสิ่งที่รู้อยู่แล้วเท่านั้น) — ข้อดี: ค่า f ที่ตัวเองยืน "ไม่มีวันแย่ลง" ข้อเสียร้ายแรง: เมื่อยืนบน local optimum (หลุมที่เพื่อนบ้านรอบๆ แย่กว่าหมด) จะ ติดตรงนั้นตลอดกาล เพราะทุกก้าวที่จะพาออกจากหลุมต้อง "แย่ลงชั่วคราว" ซึ่งกฎห้าม!

[10, 7, 5, 4, 6, 3, 2, 1, 3, 5, 9] — local min ที่ตำแหน่ง 3 (ค่า 4) และ 7 (ค่า 1 = global), ก้าวสุ่ม = ±1 จากการโยนเหรียญ
ทดลองที่ 1 — เริ่มที่ตำแหน่ง 1 (ค่า 7):
• ก้าว 1: เสนอ 2 (ค่า 5) → 5 < 7 รับ → ยืนที่ 2
• ก้าว 2: เสนอ 3 (ค่า 4) → 4 < 5 รับ → ยืนที่ 3
• ก้าว 3: เสนอ 4 (ค่า 6) → 6 > 4 ปฏิเสธ / ก้าว 4: เสนอ 2 (ค่า 5) → ปฏิเสธ / ก้าว 5: เสนอ 4 → ปฏิเสธ …
→ ติดตรงตำแหน่ง 3 (ค่า 4) ตลอดกาล ทั้งที่ global คือตำแหน่ง 7 (ค่า 1) — เพราะทุกทางออกจากหลุมต้อง "ขึ้นเขา" ซึ่งถูกกฎห้าม

💡 เทคนิคตีโจทย์ เจอ "ยอมรับเฉพาะก้าวที่ดีขึ้น / reject any worse move" → ตอบ Stochastic Hill Climbing และข้อสรุปที่ต้องพ่วงมาด้วยเสมอ: "จึงติด local optimum ได้ (cannot escape local optima)" — ข้อสอบชอบถามต่อว่า "แล้วเกิดอะไรขึ้น" อย่าลืมตอบครึ่งหลัง!

3.4 ผลของขนาดก้าว (Step Size) และสัญญาณอัตราการยอมรับ 20–50%

สัญชาตญาณ: เดินลงหุบเขา — ก้าวสั้นเกิน = คุ้ยไปทีละเซนติเมตร ไม่มีวันถึงก้น ก้าวยาวเกิน = ก้าวทีละกิโลเมตร ข้ามหลุมไปตกอีกฟากเสมอ — ปัญหาคือเรา "มองไม่เห็น" ว่าก้าวเราเหมาะไหม … แต่จริงๆ เรามี สายวัดฟรี คือนับว่า "ก้าวที่เสนอไป กี่ก้าวที่ดีขึ้นจนถูกรับ"

อัตราการยอมรับ (Acceptance rate): = (จำนวนก้าวที่ถูกยอมรับ) ÷ (จำนวนก้าวที่เสนอทั้งหมด) — เช่น เสนอ 100 ก้าว รับ 30 = 30% — เป็น "สัญญาณฟรี" ที่บอกความเหมาะของขนาดก้าวโดยไม่ต้องรู้สูตร f
อาการAcceptance rateเกิดอะไรขึ้นวิธีแก้
ก้าวเล็กเกินสูงกว่า 50%แทบทุกก้าวดีขึ้น (เพราะแค่ขยับนิดเดียวย่อมไม่แย่ลง) แต่คืบแบบหนอน เผางบไปกับก้าวจิ๋วขยายขนาดก้าว
ก้าวใหญ่เกินต่ำกว่า 20%ก้าวส่วนใหญ่กระโดดข้ามหลุมไปตกจุดแย่กว่า → โดนปฏิเสธเป็นส่วนใหญ่ แทบไม่ขยับหดขนาดก้าว
ก้าวพอดี20–50%กำลังก้าวผ่านระยะที่ "มีประโยชน์" พอดี — ได้ทั้งความก้าวหน้าและความแม่นยำคงไว้ / จูนต่อเนื่อง
🩵 ตัวอย่างจับมือทำ 3.4 — อ่านสัญญาณแล้วสั่งแก้ (โจทย์คำนวณแบบนี้ออกแน่) โจทย์ (a): อัลกอริทึมเสนอก้าว 1,000 ครั้ง ถูกยอมรับ 850 ครั้ง — สรุปและสั่งแก้?
• อัตราการยอมรับ = 850 ÷ 1,000 = 85%
• 85% > 50% → ก้าวเล็กเกินไป → สั่ง: เพิ่มขนาดก้าว
โจทย์ (b): เสนอ 1,000 ครั้ง รับ 90 ครั้ง
• = 90 ÷ 1,000 = 9% < 20% → ก้าวใหญ่เกินไป (ส่วนใหญ่กระโดดพลาด) → สั่ง: ลดขนาดก้าว
โจทย์ (c): เสนอ 1,000 ครั้ง รับ 350 ครั้ง
• = 350 ÷ 1,000 = 35% → อยู่ในโซน 20–50% → ขนาดก้าวกำลังดี คงไว้
กฎปรับอัตโนมัติที่ใช้จริง: ถ้า rate > 50% → คูณขนาดก้าวด้วย 2 / ถ้า rate < 20% → หารด้วย 2 — ปรับไปเรื่อยๆ จนเข้าโซน
💡 เทคนิคตีโจทย์ เจอตัวเลข "เสนอ N ก้าว รับ M ก้าว" → คิด M/N เทียบกับ 20–50% ทันที: > 50% = ก้าวเล็กเกิน (เพิ่ม step size) / < 20% = ก้าวใหญ่เกิน (ลด step size) / 20–50% = พอดี — จำช่วงตัวเลขนี้ให้ขึ้นใจ เป็นโจทย์โปรดของผู้ออกสอบ

3.5 ปัญหาการติดกับดักเฉพาะที่ (Local Traps — โลคัล แทร็ปส์)

  • Local optimum (หลุมตื้น): ล้อมรอบด้วยที่สูง — กฎ "รับเฉพาะดีขึ้น" ทำให้หนีไม่พ้น (เห็นแล้วในตัวอย่าง 3.3)
  • Plateau (แพลโต — ที่ราบ): เพื่อนบ้านรอบๆ มีค่า f เท่ากันหมด — ไม่มีสัญญาณบอกทิศเลย เพราะ "ไม่ดีขึ้น = ไม่ถูกยอมรับ" จึงเหมือนยืนกลางทะเลทรายราบเป็นแป้ง หมุนไปหมุนมาก็อยู่ที่เดิม
  • Ridge (ริดจ์ — สันเขาเฉียง): หุบเขาที่วิ่งเฉียง (ทแยง) ระหว่างแกน — ก้าวตรงตามแกน x หรือ y กลับ "ขึ้นเขา" ทั้งคู่ มีแต่ก้าวทแยงเท่านั้นที่ลง ถ้าอัลกอริทึมเสนอก้าวตามแกนอย่างเดียว จะติดตรงสันตลอด
🩵 ตัวอย่างจับมือทำ 3.5 — เห็นกับดัก Ridge ด้วยตัวเลขจริง โจทย์: $f(x, y) = (x-y)^2 + 0.1(x+y)^2$ — หุบเขานี้วิ่งเฉียงตามเส้น y = x (ลองแทนดู: จุดไหนที่ x = y จะได้ f เล็กมาก) — กำลังยืนที่ (3, −3) และอนุญาตให้ก้าวได้ทีละ 1 ตามแกน x หรือ y เท่านั้น
ค่า ณ จุดปัจจุบัน: $f(3,-3) = (3-(-3))^2 + 0.1(3+(-3))^2 = 6^2 + 0.1(0)^2 = 36 + 0 = 36$
ลองก้าวตามแกน:
• ก้าว x ไป (4, −3): $(4+3)^2 + 0.1(4-3)^2 = 49 + 0.1 = 49.1$ → แย่ลง (49.1 > 36) ปฏิเสธ ✗
• ก้าว y ไป (3, −4): $(3+4)^2 + 0.1(3-4)^2 = 49 + 0.1 = 49.1$ → แย่ลง ปฏิเสธ ✗
• ก้าว x กลับ (2, −3): $(2+3)^2 + 0.1(-1)^2 = 25.1$ → แย่ลง ✗ / ก้าว y กลับ (3, −2): $(5)^2 + 0.1(1)^2 = 25.1$ → ✗
ลองก้าวทแยง (2, −2): $(2-(-2))^2 + 0.1(2+(-2))^2 = 4^2 + 0 = 16$ → ดีขึ้นมาก! รับ ✓
สรุป: ก้าวตามแกนทั้ง 4 ทิศพาแย่ลงหมด มีแต่ก้าวทแยงเท่านั้นที่ลงหุบ — Hill Climbing ที่เสนอก้าวตามแกนจะ "ติดสันเขา" ไม่รู้จบ

3.6 Iterated Local Search (ILS) vs Random Restarts — กับ Big Valley Hypothesis

เมื่อติดกับดักเฉพาะที่แล้ว มี 2 ยุทธศาสตร์หลักในการ "หนี":

  • Random Restarts (แรนดอม รีสตาร์ท — เริ่มใหม่แบบสุ่ม): โยนทุกอย่างทิ้ง เริ่มสุ่มจุดใหม่จากศูนย์ — เหมือนยกเลิกเกมแล้วเปิดเกมใหม่เลย
  • Iterated Local Search — ILS (ไอเทอเรเต็ด โลคัล เซิร์ช — ค้นเฉพาะที่แบบวนซ้ำ): จากคำตอบที่ติด local → เตะ (perturb/kick — เปอร์เทิร์บ: สั่น/ดีด) ออกจากหลุมแรงพอควร → ให้ local search วิ่งต่อ → จดค่าดีที่สุด → เตะซ้ำอีก — เหมือนเด้งลูกบอลขึ้นจากหลุมพอให้กลิ้งไปหลุมอื่น แต่ไม่ทิ้งแผนที่เดิม
Big Valley Hypothesis (สมมติฐานหุบเขาใหญ่): ในปัญหาจริงจำนวนมาก local optimum ที่ "ดี" มักกระจุกอยู่ใกล้ๆ กัน ในหุบเขาใหญ่รอบ global optimum — ถ้าสมมติฐานนี้จริง การเริ่มจากคำตอบดีเดิมแล้วเตะนิดๆ (ILS) ดีกว่าเริ่มสุ่มใหม่หมด เพราะเรายืนอยู่ใน "ย่านที่ดีทั้งย่าน" อยู่แล้ว การโยนทิ้ง = ทิ้งข้อมูลล้ำค่า
ประเด็นRandom RestartsIterated Local Search (ILS)
เริ่มจากไหนจุดสุ่มใหม่ล้วนๆ ทุกรอบคำตอบดีเดิม + kick แรงพอควร
ข้อมูลเก่าทิ้งหมดเก็บไว้ใช้ (เชื่อ Big Valley)
เหมาะกับภูมิประเทศแบบสุ่ม ไม่มีโครงสร้างมีหุบเขาใหญ่ คำตอบดีกระจุกกัน
ความเสี่ยงเปลืองงบ เริ่มจากศูนย์เสมอkick เบาไป = กลับหลุมเดิม / แรงไป = กลายเป็น restart ใหม่เปล่าๆ
🩵 ตัวอย่างจับมือทำ 3.6 — แข่ง ILS กับ Restarts บนภูมิประเทศเดียวกัน โจทย์: ภูมิประเทศมี local optimum ที่ตำแหน่ง A(2) ค่า f=8, B(5) ค่า f=4, C(9) ค่า f=1 (global) — สังเกตว่า B และ C อยู่ "ใกล้" A (Big Valley)
วิธี Restarts (งบ 3 รอบ):
• รอบ 1: สุ่มเจอ → ลงหลุม A (f=8) / รอบ 2: สุ่มใหม่ → หลุม D(12) ค่า f=6 / รอบ 3: สุ่มใหม่ → หลุม B (f=4)
• ดีที่สุด = f 4 (ยังไม่เจอ global!) — เพราะแต่ละรอบ "ลืม" ความรู้รอบก่อน
วิธี ILS (งบเท่ากัน):
• เริ่มได้ A (f=8) → เตะไปตำแหน่ง 4 (ใกล้ B!) → local search → เจอ B (f=4) ดีขึ้น จดสถิติ
• เตะจาก B ไปตำแหน่ง 7 (ใกล้ C!) → local search → เจอ C (f=1) = global!
สรุป: ILS ชนะเพราะ "เตะแบบมีทิศ" — จาก local ที่ดี การเตะเบาๆ มักไปตกแถวๆ local ดีตัวอื่น (สอดคล้อง Big Valley) ขณะที่ restart โยนเต๋าใหม่ทั้งลูก
💡 เทคนิคตีโจทย์ เจอ "คำตอบที่ดีมักอยู่ใกล้กัน / มีหุบเขาใหญ่ / Big Valley" → เลือก ILS — เจอ "ภูมิประเทศสุ่ม ไม่มีโครงสร้าง" → เลือก Random Restarts — และถามถึง kick strength (ความแรงเตะ) ให้ตอบ: เบาไป = กลับหลุมเดิม แรงไป = เท่ากับ restart ใหม่ ต้อง "แรงพอดี"

3.7 การออกแบบการทดลองและการรายงานผลเชิงสถิติ

อัลกอริทึมแบบสุ่มมี "โชค" เข้ามาเกี่ยวข้อง — รันครั้งเดียวแล้วชนะ ไม่พิสูจน์อะไรเลย (อาจแค่โชคดี) การเปรียบเทียบที่น่าเชื่อถือต้องมีหลัก 4 ข้อ:

  1. รันอิสระ ≥ 30 ครั้ง (independent runs — การทดลองอิสระ): แต่ละรันใช้ random seed (เมล็ดการสุ่ม) ต่างกัน — หนึ่งรัน = ตัวอย่างหนึ่งชิ้น ต้องมีตัวอย่างพอหลายชิ้นถึงจะสรุปได้ (เลข 30 มาจากหลักสถิติว่าประมาณนี้ค่าเฉลี่ยเริ่มเสถียร)
  2. งบเท่ากัน (equal budget): ทุกอัลกอริทึมได้เรียก f จำนวนครั้งเท่ากันพอดี (budget จากหัวข้อ 1.6) — เทียบคนวิ่งระยะไม่เท่ากัน = ไม่มีความหมาย
  3. รายงาน Success rate (อัตราความสำเร็จ) เมื่อการแจกแจงเป็น 2 ยอด: ถ้าผลลัพธ์ออกมาเป็น 2 กลุ่มขั้ว (เช่น เจอคำตอบสุดยอด vs ติดหลุมแย่) ค่าเฉลี่ย (mean — มีน) จะ หลอกเรา เพราะมันเป็นตัวเลข "หัวหักหาง" ที่ไม่ตรงกับผลจริงของรันใดเลย — ต้องรายงานสัดส่วนรันที่สำเร็จแทน (หรือรายงานควบคู่กัน)
  4. รายงานครบชุด: ไม่ใช่แค่ค่าเฉลี่ย ให้รายงาน best / worst / median (มีเดียน — ค่ากลาง) หรือกล่องกระจาย (box plot) เพื่อให้เห็น "ความกระจาย" ของผล
🩵 ตัวอย่างจับมือทำ 3.7 — เห็นตอนที่ "ค่าเฉลี่ยหลอกเรา" (โจทย์คลาสสิก!) โจทย์: แข่งอัลกอริทึม A กับ B บนปัญหาที่คำตอบสมบูรณ์แบบคือ f = 0 (แสดงผลเป็นตาราง 10 รันเพื่อความง่ายในการคำนวณ — ของจริงต้อง ≥ 30):
• A: [0, 0, 0, 0, 0, 0, 0, 0, 0, 100] (สำเร็จ 9 รัน ติดหลุมแย่ 1 รัน)
• B: [8, 8, 8, 8, 8, 8, 8, 8, 8, 8] (ได้ค่ากลางๆ ทุกรัน)
คำนวณค่าเฉลี่ย (mean):
• ค่าเฉลี่ย A = (0+0+…+0+100) ÷ 10 = 100 ÷ 10 = 10
• ค่าเฉลี่ย B = 80 ÷ 10 = 8
อ่านผลแบบผิวเผิน: 8 < 10 → "B ดีกว่า A" ← นี่คือหลอกลวง!
คำนวณ Success rate (เกณฑ์สำเร็จ: f ≤ 1):
• A: สำเร็จ 9 จาก 10 = 90% / B: สำเร็จ 0 จาก 10 = 0%
อ่านผลที่ถูกต้อง: การแจกแจงของ A เป็น 2 ยอด (bimodal) — ก้อนใหญ่ที่ 0 กับก้อนเล็กที่ 100 ค่าเฉลี่ย 10 คือ "หัวหักหาง" ไม่ตรงกับรันจริงแม้แต่รันเดียว ส่วน B มั่นคงแต่ขีดจำกัดต่ำ → ถ้าต้องการ "โอกาสเจอคำตอบสมบูรณ์" เลือก A (90% success) — เมื่อเห็น 2 ยอด ให้รายงาน success rate แทน mean เสมอ
⚠️ จุดที่ข้อสอบชอบหลอก (1) เทียบอัลกอริทึมด้วย "เวลา" หรือ "จำนวนรันไม่เท่ากัน" = ไม่แฟร์ — ต้องใช้ budget เท่ากัน (2) ใช้ mean ตัดสินเมื่อผลเป็น 2 ยอด = หลอกตัวเอง — ข้อสอบมักให้ข้อมูลแบบตัวอย่างข้างบน (มีค่า outlier ตัวเดียวดูดค่าเฉลี่ย) แล้วถามว่า "ควรรายงานอะไร" → ตอบ Success rate
💡 เทคนิคตีโจทย์ เจอ "การเปรียบเทียบที่เป็นธรรม / fair comparison" → ตอบ 3 ชุด: (1) รันอิสระ ≥ 30 ครั้ง (ต่าง seed) (2) budget เท่ากัน (3) ผลเป็น 2 ยอด → รายงาน success rate แทน mean

4เกรเดียนต์เดสเซนต์

Gradient Descent (เกรเดียนต์ ดีเซนต์ — การไหลลงตามความชัน) — หัวใจของการเทรน Machine Learning ทั้งหมด: $x \leftarrow x - \eta\nabla f$

ศัพท์บทที่ 4 (อ่านว่า)แปลว่าความหมายในวิชานี้
Derivative (ดีริเวทีฟ)อนุพันธ์ความชันของกราฟ ณ จุดหนึ่ง
Partial derivative (พาร์เชียล ดีริเวทีฟ)อนุพันธ์ย่อยความชันรายแกน (ถือตัวแปรอื่นนิ่ง)
Gradient (เกรเดียนต์)เวกเตอร์ความชันรวมอนุพันธ์ย่อยทุกแกนมาเป็นเวกเตอร์เดียว
Steepest descent (สตีพิสต์ ดีเซนต์)ทิศลงชันที่สุดทิศที่ทำให้ f ลดเร็วที่สุด = −∇f
Learning rate η (เลิร์นนิง เรต)อัตราการเรียนรู้ตัวคูณกำหนดขนาดก้าวแต่ละรอบ
Convergence (คอนเวอร์เจนซ์)การลู่เข้าค่าเข้าใกล้จุดต่ำสุดแล้วนิ่งลง
Divergence (ไดเวอร์เจนซ์)การลู่ออกค่าหนีไกลออกไปเรื่อยๆ บานปลาย
Analytic (แอนะลิติก)เชิงวิเคราะห์หาอนุพันธ์จากกฎคณิตศาสตร์โดยตรง
Automatic differentiation (ออโตเมติก ดิฟเฟอเรนเชียชัน — AD)อนุพันธ์อัตโนมัติให้โปรแกรมจดการคำนวณแล้วคิดอนุพันธ์เป๊ะๆ ให้ (เช่น PyTorch)
Numerical (นิวเมริคัล)เชิงตัวเลขประมาณอนุพันธ์จากค่า f ที่แทนค่าใกล้กัน
Central difference (เซนทรัล ดิฟเฟอเรนซ์)ผลต่างกลางสูตรประมาณอนุพันธ์แบบ "ดูซ้าย-ขวาพร้อมกัน"
Quadratic (ควอดราติก)กำลังสองฟังก์ชันรูปชามมาตรฐาน เช่น x², xᵀAx
Contour line (คอนทัวร์ ไลน์)เส้นชั้นเส้นเชื่อมจุดที่ f เท่ากัน (เหมือนเส้นความสูงบนแผนที่)
Eigenvalue λ (ไอเกนวาลู)ค่าเอกเทศความโค้งตามแกนหลักของปัญหา

4.1 อนุพันธ์และเกรเดียนต์ในเชิงเรขาคณิต

เริ่มจาก 1 มิติ (สัญชาตญาณ): อนุพันธ์ $f'(x)$ คือ ความชัน (slope — สโลป) ของเส้นสัมผัสที่จุด x — ถ้าเดินขวาไปเล็กน้อย (ระยะ $dx$) ค่า f จะเปลี่ยนไปประมาณ $f'(x) \cdot dx$ ชันมาก = ค่า f เปลี่ยนเร็ว, ชันเป็นศูนย์ = ราบ (จุดต่ำสุด/สูงสุด)

$$\nabla f = \left( \frac{\partial f}{\partial x_1}, \frac{\partial f}{\partial x_2}, \dots, \frac{\partial f}{\partial x_n} \right)$$เกรเดียนต์ = รวม "ความชันรายแกน" ทุกแกนมาเรียงเป็นเวกเตอร์เดียว
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$\nabla$ ("นาบลา / เดล")สัญลักษณ์รูปสามเหลี่ยมคว่ำ — แปลว่า "รวมอนุพันธ์ย่อยทุกแกน" เมื่อวางหน้า f จะได้เวกเตอร์ความชัน
$\partial$ ("พาร์เชียล / ดี รอบ")"อนุพันธ์ย่อย" — หาความชันเฉพาะแกนนั้นโดย ถือตัวแปรอื่นนิ่ง เหมือนถามว่า "ถ้าขยับแค่ x, y นิ่งๆ f เปลี่ยนกี่หน่วยต่อ 1 หน่วยของ x?"
$\nabla f$ ("เกรเดียนต์ เอฟ")เวกเตอร์ชี้ไปทางที่ f เพิ่มเร็วที่สุด — ขนาด (ความยาวเวกเตอร์) = ความชันเท่าไหร่ ทิศ = ขึ้นชันทางไหน
🩵 ตัวอย่างจับมือทำ 4.1 — คำนวณเกรเดียนต์ทีละแกน โจทย์: $f(x, y) = x^2 + 3y^2$ — หา $\nabla f$ ที่จุด $(1, 2)$
ขั้น 1 — ชันแกน x (ถือ y นิ่ง): $\dfrac{\partial f}{\partial x} = 2x$ → แทน x = 1 → $\dfrac{\partial f}{\partial x} = 2$
ขั้น 2 — ชันแกน y (ถือ x นิ่ง): $\dfrac{\partial f}{\partial y} = 6y$ → แทน y = 2 → $\dfrac{\partial f}{\partial y} = 12$
ขั้น 3 — รวมเป็นเวกเตอร์: $\nabla f(1,2) = (2, 12)$
อ่านความหมาย: ณ จุดนี้ ถ้าขยับ x ไป 1 หน่วย f เพิ่มราว 2 หน่วย แต่ถ้าขยับ y ไป 1 หน่วย f เพิ่มราว 12 หน่วย → ทิศ y ชันกว่ามาก → เวกเตอร์ (2, 12) เลย "เอียงไปทาง y" เพราะเกรเดียนต์ชี้ไปทางที่ขึ้นชันแรงสุด

4.2 ทำไม −∇f จึงเป็นทิศที่ลดค่าเร็วที่สุด (Steepest Descent)

สัญชาตญาณก่อน: ยืนอยู่ริมเนิน รอบตัวเดินได้ 360 องศา — ทุกทิศ "ชันไม่เท่ากัน" มีทิศหนึ่งที่ขึ้นชันแรงสุด และทิศ ตรงข้ามพอดี คือทิศที่ลงชันแรงสุด — เกรเดียนต์จดจำทิศ "ขึ้นแรงสุด" ไว้ให้เรา แล้วเราแค่กลับหัว (ใส่ลบ) ก็ได้ทิศ "ลงแรงสุด"

$$\text{อัตราการเปลี่ยนแปลงของ } f \text{ ในทิศ } u = \nabla f \cdot u = \|\nabla f\| \cos\theta$$θ = มุมระหว่างเกรเดียนต์กับทิศที่เราเดิน — สูตรนี้คือใบเบิกทางของทั้งหัวข้อ
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$u$ ("ยู")เวกเตอร์ "ทิศทางที่เราเลือกเดิน" (ยาว 1 หน่วย — เป็นแค่เข็มทิศ ไม่มีระยะ)
$\nabla f \cdot u$ ("ด็อท โปรดัคต์")ผลคูณจุด = "ความชันที่เจอจริงเมื่อเดินทิศ u" — บวก = ขึ้นเขา, ลบ = ลงเขา, ศูนย์ = ราบตามขวาง
$\|\nabla f\|$ ("นอร์ม / ขนาดเกรเดียนต์")ความยาวของเวกเตอร์เกรเดียนต์ = ความชันแรงสุดเท่าที่มีในจุดนี้
$\cos\theta$ ("โคไซน์ ธีต้า")ตัวคูณลดหลั่นจาก 1 ถึง −1: เดินทางเดียวกับเกรเดียนต์ (θ=0°) ได้เต็ม ๆ / ตั้งฉาก (90°) ได้ 0 / เดินสวน (180°) ได้ลบเต็ม ๆ

เหตุผลจบใน 3 บรรทัด: เนื่องจาก $\cos\theta$ มีค่ามากที่สุด = +1 เมื่อเดิน "ทางเดียวกับ" เกรเดียนต์ (θ = 0°) → นั่นคือทิศ ขึ้นเร็วสุด และ $\cos\theta$ น้อยที่สุด = −1 เมื่อเดิน "สวน" เกรเดียนต์ (θ = 180°) → นั่นคือทิศ ลงเร็วสุด = ทิศของ $-\nabla f$ นั่นเอง ไม่มีทิศไหนลงเร็วกว่านี้อีกแล้ว

🩵 ตัวอย่างจับมือทำ 4.2 — ทดลองเดินทุกทิศแล้วเทียบด้วยตัวเลข โจทย์: ณ จุดหนึ่ง $\nabla f = (3, 4)$ — ทิศไหนลงชันแรงสุด? ลองเดิน 4 ทิศเทียบกัน
ขั้น 0 — ขนาดเกรเดียนต์: $\|\nabla f\| = \sqrt{3^2 + 4^2} = \sqrt{25} = 5$
ทิศที่ 1 — ขวา: $u = (1, 0)$ → อัตรา = $3(1) + 4(0) = 3$ (ขึ้น แต่ไม่แรงสุด)
ทิศที่ 2 — ขึ้น: $u = (0, 1)$ → $3(0) + 4(1) = 4$ (ขึ้นแรงกว่า แต่ยังไม่สุด)
ทิศที่ 3 — ตามเกรเดียนต์: $u = (0.6, 0.8)$ (= (3,4)/5 ทำให้ยาว 1) → $3(0.6) + 4(0.8) = 1.8 + 3.2 = \mathbf{+5}$ → ขึ้นชันสุด (เท่ากับ ‖∇f‖ พอดี ตามสูตร cos θ = 1)
ทิศที่ 4 — สวนเกรเดียนต์: $u = (-0.6, -0.8)$ → $3(-0.6) + 4(-0.8) = \mathbf{-5}$ → ลงชันสุด! (ลบเต็มที่ cos θ = −1)
สรุป: ทิศลงชันแรงสุด = $-\nabla f = (-3, -4)$ (ทิศตรงข้ามเกรเดียนต์เป๊ะ) — และไม่ว่าลองทิศไหน ค่าจะอยู่ระหว่าง −5 ถึง +5 เสมอ เพราะ cos θ อยู่ระหว่าง −1 ถึง 1
💡 เทคนิคตีโจทย์ เจอ "ทำไมต้องเดินตาม −∇f / justify steepest descent" → ตอบสั้นๆ 3 ประโยค: (1) อัตราการเปลี่ยนแปลงในทิศ u คือ $\nabla f \cdot u = \|\nabla f\|\cos\theta$ (2) cos θ ต่ำสุด = −1 ที่มุม 180° (3) เดินสวนเกรเดียนต์จึงลด f เร็วที่สุด — สังเกตด้วยว่า ∇f "ตั้งฉากกับเส้นชั้น (contour)" เป็นข้อสอบยอดนิยม

4.3 กฎการปรับปรุง (Update Rule) และขนาดก้าวจริง

$$x_{new} = x - \eta\, \nabla f(x)$$"จุดใหม่ = จุดเดิม ลบด้วย เอทา × เกรเดียนต์" — สมการเดียวที่ขับเคลื่อนการเทรน AI ทั้งโลก
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$x_{new}$ ("เอ็กซ์ นิว")ตำแหน่งหลังก้าว 1 ครั้ง — จะเอาไปแทน x เดิม แล้วก้าวต่ออีกรอบ
$\eta$ ("เอทา / อีตา" — ตัวอักษรกรีก eta)Learning rate — อัตราการเรียนรู้: ตัวเลขบวกเล็กๆ ที่เราตั้งเอง เป็น "พวงมาลัย" คุมขนาดก้าว (เช่น 0.01, 0.1, 0.3)
เครื่องหมาย − (ลบ)หัวใจของสูตร! เดิน "สวน" เกรเดียนต์ เพราะ ∇f ชี้ขึ้นชันแรงสุด การสวนทาง = ลงชันแรงสุด (จากหัวข้อ 4.2)
$\eta\nabla f(x)$"เวกเตอร์ก้าว" — ทั้งทิศ (สวนเกรเดียนต์) และระยะ (ยาวเท่า η × ขนาดเกรเดียนต์) อยู่ในตัวเดียว
ขนาดก้าวจริง (Actual step length) = $\eta\,\|\nabla f\|$: เวกเตอร์ก้าว $-\eta\nabla f$ มีความยาว $= \eta \times \|\nabla f\|$ — ผลสำคัญ: ใกล้ก้นชาม ∇f เล็กลง → ก้าวเล็กลงเองโดยอัตโนมัติ (เบรกอัตโนมัติในตัว) เพราะยิ่งใกล้ก้น พื้นยิ่งราบ ความชันยิ่งน้อย
🩵 ตัวอย่างจับมือทำ 4.3 — ก้าวหนึ่งครั้ง คำนวณครบทุกชิ้น (ไม่ข้ามขั้น) โจทย์: $f(x, y) = x^2 + 2y^2$ ยืนที่ $(2, 1)$ ใช้ $\eta = 0.1$ — ก้าวหนึ่งครั้งแล้วได้อะไร?
ขั้น 1 — หาเกรเดียนต์ ณ จุดปัจจุบัน: $\dfrac{\partial f}{\partial x} = 2x = 4$, $\dfrac{\partial f}{\partial y} = 4y = 4$ → $\nabla f(2,1) = (4, 4)$
ขั้น 2 — คำนวณขนาดเกรเดียนต์: $\|\nabla f\| = \sqrt{4^2 + 4^2} = \sqrt{32} \approx 5.657$
ขั้น 3 — ขนาดก้าวจริง: $\eta\|\nabla f\| = 0.1 \times 5.657 = 0.566$ หน่วย (เดินเอียงทแยงไปทาง (−4, −4))
ขั้น 4 — อัปเดตตำแหน่ง: $x_{new} = (2, 1) - 0.1(4, 4) = (2 - 0.4,\ 1 - 0.4) = (1.6,\ 0.6)$
ขั้น 5 — ตรวจว่าดีขึ้นจริงไหม: ก่อนก้าว $f(2,1) = 4 + 2 = 6$ / หลังก้าว $f(1.6, 0.6) = 2.56 + 0.72 = 3.28$ → ลดจาก 6 → 3.28 ✓
อ่านผล: หนึ่งก้าวลดค่า f ลงเกือบครึ่ง — ทำซ้ำขั้น 1–5 ไปเรื่อยๆ ค่าจะคืบเข้าหา (0, 0) ซึ่งเป็นก้นชาม

4.4 การหาอนุพันธ์ 3 วิธี: Analytic, Automatic, Numerical

1. Analytic (แอนะลิติก — วิเคราะห์จากกฎ)
ใช้กฎอนุพันธ์ (กฎกำลัง, กฎลูกโซ่) หาสูตรตรงๆ → เป๊ะ 100% แต่ต้องรู้สูตร f และคำนวณมือเอง
2. Automatic Differentiation — AD (ออโตเมติก — อนุพันธ์อัตโนมัติ)
ให้โปรแกรม "จดทุกการคำนวณ" ที่ทำกับ x แล้วย้อนใช้กฎลูกโซ่อัตโนมัติ → เป๊ะเท่าเครื่องคิดเลข — นี่คือสิ่งที่ PyTorch/TensorFlow ทำตอนเทรน (backpropagation — แบ็กโพรพาเกชัน: การส่งความผิดพลาดย้อนกลับ)
3. Numerical — Central Difference (นิวเมริคัล — ผลต่างกลาง)
ไม่รู้สูตรเลยก็ทำได้! แค่ "แตะ f ซ้าย-ขวา" รอบจุดที่สนใจ แล้วหารระยะ → ค่าประมาณ (เหมาะกับ black-box): $f'(x) \approx \dfrac{f(x+h) - f(x-h)}{2h}$
$$f'(x) \approx \frac{f(x+h) - f(x-h)}{2h}$$"ค่า f ที่ขวา ลบ ค่า f ที่ซ้าย หารด้วยระยะซ้ายขวารวม" — ความชันของเส้นตัดผ่านสองจุดรอบจุดสนใจ
สัญลักษณ์ (อ่านว่า)คืออะไร / ภาษาคนทั่วไป
$h$ ("เอช")ขนาดช่วงขยับไปแตะ f (เช่น 0.1) — เล็กพอให้เส้นตัดใกล้เคียงเส้นสัมผัส แต่ไม่เล็กเกินจนค่า f ที่ลบกัน "แทบไม่ต่าง" แล้วเกิดความคลาดเคลื่อนจากการปัดทศนิยม
$f(x+h)$ / $f(x-h)$ค่า f ที่ "แตะจุดขวา" / "แตะจุดซ้าย" รอบจุด x — การใช้ทั้งสองข้าง (กลาง) ทำให้ความคลาดเคลื่อนซ้าย-ขวา "หักล้างกัน"
Forward difference (ฟอร์เวิร์ด — ผลต่างหน้า)เวอร์ชันใช้แค่จุดข้างหน้า: $\frac{f(x+h)-f(x)}{h}$ — ง่ายกว่าแต่คลาดเคลื่อนมากกว่า (เทียบให้ดูในตัวอย่าง)
🩵 ตัวอย่างจับมือทำ 4.4 — รันทั้ง 3 วิธีบนโจทย์เดียวกัน แล้วเทียบความเป๊ะ โจทย์: $f(x) = x^3$ — หา $f'(2)$ ด้วยทั้ง 3 วิธี (ให้ h = 0.1)
วิธี 1 — Analytic: กฎกำลัง: $f'(x) = 3x^2$ → $f'(2) = 3(4) = \mathbf{12}$ ← ค่าจริง (ground truth)
วิธี 2 — Numerical แบบ central difference:
• ขั้น 1: $f(2.1) = 2.1^3 = 9.261$ / $f(1.9) = 1.9^3 = 6.859$
• ขั้น 2: ผลต่าง $= 9.261 - 6.859 = 2.402$
• ขั้น 3: หาร $2h = 0.2$ → $2.402 / 0.2 = \mathbf{12.01}$ (คลาดเคลื่อนแค่ 0.01 — ใกล้เคียงมาก!)
วิธี 3 — Numerical แบบ forward difference (เทียบให้เห็นว่าแย่กว่า):
• $(f(2.1) - f(2))/0.1 = (9.261 - 8)/0.1 = 1.261/0.1 = \mathbf{12.61}$ (คลาดเคลื่อน 0.61 — แย่กว่าถึง 61 เท่า! เพราะไม่มีการหักล้างซ้าย-ขวา)
โบนัส — AD ทำงานอย่างไร: ให้ $f(x) = x(x+1)$ ที่ x = 3: โปรแกรมจดว่า "a = x+1 = 4 แล้ว f = x·a = 12" ตอนย้อนกลับ: $\partial f/\partial a = x = 3$ และ $\partial a/\partial x = 1$ → $f' = 3 \times 1 + 4 \times 1 = 7$ — เทียบสูตรตรง: $f = x^2+x \Rightarrow f' = 2x+1 = 7$ ✓ เป๊ะไม่มีคลาดเคลื่อน
วิธีเป๊ะไหมต้องรู้สูตร f ไหมใช้เมื่อไหร่
Analyticเป๊ะ 100%ต้องรู้ + คำนวณมือฟังก์ชันเล็ก สูตรชัดเจน
Automatic (AD)เป๊ะ (ระดับเครื่อง)ไม่ต้องคำนวณมือ แต่ต้องเขียนโค้ดผ่านไลบรารี ADDeep Learning / โมเดลใหญ่ (PyTorch, TensorFlow)
Numerical (central)ประมาณ (คลาดเคลื่อนตาม h)ไม่ต้องรู้เลย — แค่เรียก f ได้Black-box! เช่น ตรวจโค้ด หรือเรียก simulation ภายนอก
⚠️ จุดที่ข้อสอบชอบหลอก (1) Numerical ใช้กับ black-box ได้ แต่ AD/Analytic ใช้ไม่ได้ถ้าไม่มีสูตร — อย่าตอบสลับ! (2) อนุพันธ์เชิงตัวเลขต้องเรียก f 2 ครั้ง (ซ้าย+ขวา) ต่อ 1 อนุพันธ์ — แพงกว่า Analytic ที่คำนวณสูตรรวดเดียว (3) ระวังสับสน central (ซ้าย+ขวา หาร 2h) กับ forward (หน้าอย่างเดียว หาร h)
💡 เทคนิคตีโจทย์ โจทย์ให้ f, จุด x และ h → เทมเพลตตอบ: แทนค่า $f(x+h)$ และ $f(x-h)$ → ลบกัน → หาร $2h$ → เทียบกับค่าจริงจากสูตร — อย่าลืมว่าตัวหารคือ 2h (จุดตายของนักศึกษาทั้งห้องคือลืม "2")

4.5 ผลของอัตราการเรียนรู้ (Learning Rate η): เล็กเกิน / พอดี / ลู่ออก

สัญชาตญาณ: η คือ "พวงมาลัย+คันเร่ง" — หมุนเบาไป รถครวญคืบไปถึงปลายทางช้ามาก หมุนพอดี ไหลลื่นลงจอด หมุนแรงไป รถส่ายหางกระเด็นออกนอกถนน

🩵 ตัวอย่างจับมือทำ 4.5 — เดินจริง 3 รอบด้วย η ต่างกัน (ฟังก์ชันเดียว จุดเริ่มเดียว) โจทย์: $f(x) = x^2$ (ชันคือ $f'(x) = 2x$) เริ่มที่ $x_0 = 3$ — กฎ: $x_{new} = x - \eta(2x) = (1 - 2\eta)\,x$ ← สังเกตว่าทุกก้าวคือ "คูณด้วยค่าคงที่ (1 − 2η)"
กรณี η = 0.05 (เล็กเกิน): คูณด้วย $1 - 0.1 = 0.9$ ทุกก้าว
• $x_1 = 0.9(3) = 2.7$ → $x_2 = 0.9(2.7) = 2.43$ → $x_3 = 2.187$ → … (ลดแค่ 10% ต่อก้าว — ต้องใช้หลายสิบก้าวกว่าจะใกล้ 0 → ช้าเกิน)
กรณี η = 0.3 (พอดี): คูณด้วย $1 - 0.6 = 0.4$ ทุกก้าว
• $x_1 = 0.4(3) = 1.2$ → $x_2 = 0.48$ → $x_3 = 0.192$ → เข้าเป้าเร็วมาก ✓ (ลด 60% ต่อก้าว)
กรณี η = 1.1 (ใหญ่เกิน): คูณด้วย $1 - 2.2 = -1.2$ ทุกก้าว
• $x_1 = -1.2(3) = -3.6$ (กระเด็นข้ามก้นไปฟากซ้าย!) → $x_2 = -1.2(-3.6) = 4.32$ (เด้งกลับขวา ไกลกว่าเดิม!) → $x_3 = -5.184$ → … ขนาดโตขึ้นเรื่อยๆ = ลู่ออก (diverge) ✗
สรุปสวยงาม: พฤติกรรมทั้งหมดคุมด้วยตัวคูณ $(1 - 2\eta)$: อยู่ระหว่าง −1 ถึง 1 → หด, เท่ากับ −1 → เด้งสวิงไม่จบ, นอกช่วง → บานปลาย (และมันนำไปสู่สูตรขอบเขตในหัวข้อถัดไปพอดี!)
💡 เทคนิคตีโจทย์ โจทย์ให้เส้นทาง x₁, x₂, x₃… แล้วถามว่า η เป็นอย่างไร → เช็คสองอย่าง: (1) ขนาดลดลงต่อเนื่อง = กำลังลู่เข้า (2) ขนาดโตขึ้น/สลับข้างแล้วโต = ลู่ออก → η ใหญ่เกิน — ถ้าโจทย์ถาม "สัญญาณบอกว่า η ใหญ่เกินไหม" → ตอบ: ค่า f สลับข้าง (ซ้าย-ขวาของก้น) และ |x| โตขึ้นทุกก้าว

4.6 ขอบเขตทางทฤษฎีสำหรับฟังก์ชันกำลังสอง: $0 < \eta < 2/\lambda_{max}$

สัญชาตญาณ: ชามแต่ละใบมี "ความโค้ง" ต่างกัน — ชามแหลมชัน (โค้งแรง) ต้องก้าวเบาๆ ชามกว้างราบ ก้าวใหญ่ได้ — คำถามคือ "ใหญ่ได้สุดกี่" ทฤษฎีให้คำตอบตายตัว: น้อยกว่า 2 หารด้วยความโค้งสูงสุด

ตัวละครในสูตร:
$\lambda$ ("แลมดา" — lambda): ค่าความโค้งของชาม — ใน 1 มิติ ฟังก์ชันกำลังสองเขียนเป็น $f(x) = \frac{1}{2}\lambda x^2$ ได้เสมอ (เช่น $x^2 = \frac{1}{2}(2)x^2$ → λ = 2)
$\lambda_{max}$ ("แลมดา แม็กซ์"): ความโค้งสูงสุดในบรรดาทุกทิศ (ในหลายมิติ แต่ละทิศมีความโค้งต่างกัน = eigenvalues — ไอเกนวาลู) — ทิศที่โค้งแรงสุดคือทิศที่ระเบิดก่อน เลยต้องใช้ตัวใหญ่สุดคุมกฎ
🩵 ตัวอย่างจับมือทำ 4.6a — พิสูจน์ขอบเขตทีละบรรทัด (แต่ละบรรทัดมีเหตุผลกำกับ) ตั้งต้น: $f(x) = \frac{1}{2}\lambda x^2$ (ชามมาตรฐาน ความโค้ง λ)
บรรทัด 1 — หาความชัน: $f'(x) = \lambda x$ (อนุพันธ์ของ ½λx² — ยกเลขชี้กำลังลงคูณ)
บรรทัด 2 — แทนในกฎอัปเดต: $x_{new} = x - \eta(\lambda x) = (1 - \eta\lambda)\,x$ (ดึง x ร่วมประจักษ์ — ได้ว่าทุกก้าวคือ "คูณด้วย (1 − ηλ)")
บรรทัด 3 — เงื่อนไขลู่เข้า: ระยะห่างจากก้นชามถูกคูณด้วย $|1 - \eta\lambda|$ ทุกก้าว → จะลู่เข้าได้ต้องหดลง คือ $|1 - \eta\lambda| < 1$ (คูณด้วยจำนวนที่ |·| < 1 = หด, เท่ากับ 1 = ไม่เคลื่อนจริง, มากกว่า 1 = โต)
บรรทัด 4 — แกะค่าสัมบูรณ์: $-1 < 1 - \eta\lambda < 1$ (นิยามค่าสัมบูรณ์)
บรรทัด 5 — ลบ 1 ทั้งช่วง: $-2 < -\eta\lambda < 0$
บรรทัด 6 — คูณ −1 (ตัวเครื่องหมายพลิก!): $2 > \eta\lambda > 0$
บรรทัด 7 — หาร λ (เป็นบวก): $0 < \eta < \dfrac{2}{\lambda}$ □ (จบการพิสูจน์)
ขยายเป็นหลายมิติ: ชามหลายมิติมีความโค้งต่างกันทุกทิศ (λ₁, λ₂, …) — ทุกทิศต้องผ่านเงื่อนไข ดังนั้นทิศที่ "โค้งแรงสุด" (λ ใหญ่สุด = λ_max) คือคนคุมกฎ → $0 < \eta < \dfrac{2}{\lambda_{max}}$
🩵 ตัวอย่างจับมือทำ 4.6b — ใช้สูตรจริง: f(x) = x² เดินด้วย 3 ค่า η ขั้น 1 — หา λ: $x^2 = \frac{1}{2}(2)x^2$ → $\lambda = 2$ → ขอบเขต $0 < \eta < 2/2 = \mathbf{1}$
ขั้น 2 — ตัวคูณต่อก้าว = (1 − 2η): แล้วเดินจาก x₀ = 3 ให้ดูจริง:
ηตัวคูณ (1−2η)x₁, x₂, x₃, x₄สรุป
0.9 (ในขอบเขต)−0.8 (|·| < 1)3 → −2.4 → 1.92 → −1.536 (สลับข้างแต่หด)ลู่เข้า ✓ (ส่ายๆ แต่เข้าใกล้)
1.0 (ขอบพอดี)−1 (เป๊ะ)3 → −3 → 3 → −3สวิงไม่จบ ✗ (ไม่ลู่เข้า — เพราะนั่นแหละคือ "ขอบ")
1.1 (เกินขอบ)−1.2 (|·| > 1)3 → −3.6 → 4.32 → −5.184 (สลับข้างแล้วโต)ลู่ออก ✗ ระเบิด
ขั้น 3 — อ่านผล: ขอบเขต $0 < \eta < 2/\lambda_{max}$ ทำนายตรงเป๊ะทุกกรณี — ในขอบเขต = หด (แม้จะส่ายข้างถ้าตัวคูณติดลบ) / เกินขอบ = บานปลาย / แตะขอบ = สวิงตายตัวไม่จบ
⚠️ จุดที่ข้อสอบชอบหลอก (1) ต้องเป็น "เครื่องหมายน้อยกว่าเป๊ะ" — η = 2/λ_max พอดีไม่ลู่เข้า (สวิงไม่จบ) และ η ต้อง บวก (η ≤ 0 = ไต่ขึ้นเขา!) (2) ในหลายมิติต้องใช้ λ_max (โค้งสูงสุด) ไม่ใช่ค่าเฉลี่ยหรือค่าเล็กสุด เพราะทิศที่โค้งแรงสุดระเบิดก่อนเสมอ (3) อย่าลืม "2" — สูตรคือ 2/λ ไม่ใช่ 1/λ
💡 เทคนิคตีโจทย์ เจอ "f(x) = ½λx² หรือ x² จงหาช่วงของ η ที่รับประกันการลู่เข้า" → เทมเพลตตอบ 3 บรรทัด: (1) ดึง λ จาก f (เช่น x² → λ = 2) (2) เขียนเงื่อนไข $|1 - \eta\lambda| < 1$ (3) แกะได้ $0 < \eta < 2/\lambda$ — และถ้าโจทย์ให้ค่า λ_max มาตรงๆ ก็แทนเลขได้เลย เช่น λ_max = 4 → ตอบ 0 < η < 0.5

🎯ภาคผนวก: สรุปสูตรทั้งหมด + เช็คลิสต์ก่อนเข้าห้องสอบ

A. สูตรสำคัญรวมศูนย์ (อ่านซ้ำวันสอบ)

สูตรแปลว่า / ใช้เมื่อไหร่
$\min_{x \in S} f(x)$ และ $y = f(x)$โครงปัญหา optimization: หา x ให้ f ต่ำสุด — 3 องค์ประกอบ: x (คำตอบที่เสนอ), f (เครื่องชิม), y (คะแนนที่วัดได้)
Curse of dimensionality: จุดสำรวจโต $10^n$มิติเพิ่ม 1 → งบโต ×10 เสมอ (exponential)
เซตคอนเวกซ์: $\theta x_1 + (1-\theta)x_2 \in C$ลากเส้นสองจุดในเซต เส้นอยู่ในเซตทั้งเส้น
ฟังก์ชันคอนเวกซ์ (chord test): $f(\text{ผสม}) \le \text{ผสมของ} f$คอร์ดลอยเหนือกราฟเสมอ — ทิศ ≤ = convex, ≥ = concave
$\text{epi}\, f = \{(x,t) : f(x) \le t\}$ภูมิภาคเหนือกราฟ — f คอนเวกซ์ ⟺ epi f เป็นเซตคอนเวกซ์
อันดับ 1: $f(x_2) \ge f(x_1) + \nabla f(x_1)^\top(x_2-x_1)$ระนาบสัมผัสวางใต้กราฟเสมอ
อันดับ 2: $\nabla^2 f \succeq 0$ ทุกจุดเฮสเซียนกึ่งบวกแน่นอน = โค้งขึ้นทุกทิศ (eigenvalues ≥ 0 ทุกตัว)
3 เงื่อนไขปัญหาคอนเวกซ์: $f_0$ คอนเวกซ์ / $f_i \le 0$ คอนเวกซ์ / $h_j$ แอฟฟินเท่านั้นเช็คทีละข้อ — สมการที่ไม่แอฟฟิน = ตกรอบทันที
คอนเวกซ์ → Local = Globalเจอหลุมแถวนั้น = เจอหลุมลึกสุดประเทศ
ไม่มีข้อจำกัด: $\nabla f(x^*) = 0$จุดราบ — ใช้ได้เฉพาะไม่มีข้อจำกัด (มีกำแพง = ติดกำแพงแล้ว ∇f ≠ 0 ได้)
Random restarts: โอกาสซวยทั้งหมด $= p^R$เริ่มใหม่ R รอบอิสระ → โอกาสตายทั้งชุดลดแบบยกกำลัง
Acceptance rate = รับ ÷ เสนอ, โซนดี = 20–50%> 50% ก้าวเล็กเกิน (เพิ่ม step) / < 20% ก้าวใหญ่เกิน (ลด step)
ทดลองที่แฟร์: ≥ 30 รันอิสระ, budget เท่ากัน, 2 ยอด → รายงาน success ratemean หลอกเมื่อการแจกแจงเป็น bimodal
$\text{อัตราเปลี่ยนทิศ } u = \nabla f \cdot u = \|\nabla f\|\cos\theta$cos θ = −1 ที่ 180° → $-\nabla f$ = ทิศลงชันสุด (steepest descent) และ ∇f ตั้งฉากกับ contour
$x_{new} = x - \eta\nabla f(x)$, ขนาดก้าวจริง $= \eta\|\nabla f\|$กฎอัปเดต Gradient Descent — ใกล้ก้นชามก้าวเล็กลงเอง
Central difference: $f'(x) \approx \frac{f(x+h)-f(x-h)}{2h}$อนุพันธ์แบบตัวเลข (ใช้กับ black-box ได้) — ตัวหารคือ 2h!
$0 < \eta < 2/\lambda_{max}$ขอบเขต η ที่รับประกันลู่เข้าบนฟังก์ชันกำลังสอง (λ_max = ความโค้งสูงสุด)

B. เช็คลิสต์ 12 ข้อก่อนเข้าห้องสอบ

  1. ✅ องค์ประกอบ 3 อย่าง = X–F–Y: คำตอบที่เสนอ → เครื่องชิม → คะแนนที่วัดได้ (อย่าสลับ y กับ x!)
  2. ✅ Search space = แผนที่ตำแหน่ง / Response surface = แผนที่ + ความสูง f — สองคำนี้ต่างกัน
  3. ✅ Curse of dimensionality = จุดสำรวจโต exponential ($10^n$) ตามจำนวนมิติ
  4. ✅ เทียบอัลกอริทึมด้วย function evaluations (จำนวนครั้งเรียก f) ไม่ใช่วินาที
  5. ✅ Black-box (ไม่มีสูตร/อนุพันธ์) → ใช้วิธีสุ่ม — ห้ามตอบ Gradient Descent
  6. ✅ Chord test: $f(\text{ผสม}) \le \text{ผสมของ} f$ = convex / พลิกเป็น ≥ = concave
  7. ✅ เฮสเซียน ⪰ 0 (eigenvalues ≥ 0 ทุกจุด) = คอนเวกซ์ — จุดเดียวไม่พอ!
  8. ✅ ข้อจำกัดสมการต้องแอฟฟินเท่านั้น / อสมการ ≥ ต้องคูณ −1 ก่อนตรวจ
  9. ✅ Hill climbing รับเฉพาะดีขึ้น → ติด local เสมอ → แก้ด้วย Restarts (ภูมิประเทศสุ่ม) หรือ ILS (Big Valley)
  10. ✅ Acceptance rate 20–50% = พอดี / > 50% เพิ่ม step / < 20% ลด step
  11. ✅ $-\nabla f$ = ทิศลงชันสุด (เพราะ $\cos\theta$ ต่ำสุด −1 ที่มุม 180°) — ∇f ตั้งฉากกับ contour เสมอ
  12. ✅ $x_{new} = x - \eta\nabla f$ / ก้าวจริง $= \eta\|\nabla f\|$ / ขอบเขต $0 < \eta < 2/\lambda_{max}$ (η = ขอบพอดี → สวิงไม่จบ, เกิน → ระเบิด)
